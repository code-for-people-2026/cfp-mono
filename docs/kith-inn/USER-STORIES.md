# 街坊味（Kith Inn）用户故事

版本：v0.1 · 更新时间：2026-09-11 · 依据：[PRD v0.5](PRD.md) · 状态：待审阅

本文把 PRD 拆成可交付、可验收的用户故事，按实际使用顺序组织。业务规则以 PRD 为准；下文的 AC 编号引用 PRD 的验收，不另建一套编号。Q1～Q6 仍由 PRD 第 7 节维护，涉及它们的部分须在对应功能开发前补齐。

首版包含下列全部故事。故事顺序表达使用和依赖关系，不代表只交付菜单、推迟订餐和履约。技术实现见 [TECH-SPEC.md](TECH-SPEC.md)。

## 2. 用户故事与完成条件

### US-01 建立和维护会做的菜

**作为桃子，我希望一次录入会做的菜并确认分类，以便排菜单时直接使用，不必每周重新输入。**

入口为首次菜品池初始化，以及之后的菜品维护页面。对应 PRD 5.1。

1. 每行输入一道菜，系统展示菜名及建议的荤、素、汤分类。
2. 分类不合适时循环调整；菜名有误时返回修改。预览未确认前不写入菜品池。
3. 确认后看到加入数量；之后可以新增、改名、改分类、停用或恢复。

完成条件：空清单不能提交；只要求菜名与分类；不增加主料和荤菜数量门槛；停用菜不参与新菜单生成，历史菜单内容不被菜品修改或删除覆盖。按 AC-01 验收。

菜品不足时的排菜处理依赖 Q2，不通过阻止录入来绕开问题。

### US-02 生成符合本周安排的菜单

**作为桃子，我希望按这一周的供餐安排和荤素汤数量生成菜单，以便先把七天要做什么安排出来。**

前提是已有可用菜品；入口为“本周菜单”。对应 PRD 5.2。

1. 选择目标周及需要供餐的午晚餐，不做的餐次跳过。
2. 为本周设置统一结构，例如两荤一素一汤；另一周可使用三荤一素一汤。
3. 生成按日期组织的七天安排，同一天午晚餐一起查看。

完成条件：各周使用各自结构；同餐不重复一道菜；菜品不足以整周不重复时允许跨餐重用并尽量隔开。按 AC-02、AC-04 验收。

新周如何继承设置、已有菜单如何响应结构变更见 Q1；连一餐都排不满时的处理见 Q2。

### US-03 换菜、逐餐去汤并确认周菜单

**作为桃子，我希望只调整不满意的菜和不想做汤的餐次，再保存为可以照着做的周菜单。**

前提是目标餐次已有菜单且尚未公布。对应 PRD 5.2。

1. 对某道菜随机换一道，或从同类可用候选中手选；其他位置保持原样。
2. 周二晚上安排周三午餐、周五晚餐时，可以分别去掉这两餐的汤，公布前可以恢复。
3. 确认后进入只读周菜单总览；再次进入仍能读取已保存的安排，并可继续准备具体餐次。

完成条件：去汤只影响目标餐次，不改变荤素数量、周结构或价格；确认周菜单不会自动公布；已公布餐次不能被任何调整操作覆盖。按 AC-03、AC-05 验收，并与 US-04 联合检查锁定规则。

再次编辑的入口见 Q1；手选入口和候选轮换见 Q2。真实试用检验桃子能否直接使用这份菜单供餐，无需另抄。

### US-04 公布某餐并开放订餐

**作为桃子，我希望把确定要做的一餐发到群里，让邻居从对应入口报名，并且订餐后看到的菜与我要做的菜一致。**

前提是该餐菜单已准备好；入口为周菜单总览或餐次确认与分享。对应 PRD 5.3。

1. 核对日期、午晚餐、菜品、每份价格、截止时间及剩余份数。
2. 生成群菜单说明和小程序入口，由桃子主动发送。
3. 顾客进入对应餐次查看并报名；公布后该餐菜单锁定。

完成条件：无需读取微信群接龙；换菜、去汤、重新生成和修改周结构均不能改写已公布菜单；无法供餐时进入 US-11；仅停止接单不取消已有订单。按 AC-10、AC-11 验收。

生成文案、发群、开放和锁定的具体操作节点由 Q3 补齐；截止及容量设置由 Q6 补齐。不能把“复制文案成功”当成微信消息已经发送。

### US-05 自助订一餐并查看自己的订单

**作为顾客，我希望从群菜单直接订餐，并能找到自己的订单，确认日期、菜品、份数和收餐位置。**

前提是餐次已公布、未截止且有余量。对应 PRD 5.4。

1. 查看菜单和每份价格，填写份数、可辨认称呼及必要收餐位置，手机号可以留空。
2. 提交后直接预订成功，首次下单也不需要桃子审核或先付款。
3. 在自己的订单中查看记录；网络重试或重复点击不产生重复有效订单。

完成条件：同一顾客同一餐次至多一笔有效订单；同时订最后余量不超容量；不能查看其他人的订单；手机号留空不阻止下单。按 AC-06、AC-15、AC-20 验收。

顾客识别与访问凭据由技术规格确定，不以手机号必填替代访问保护。普通份数上限及位置字段组织见 Q6。

### US-06 私聊代下后关联本人的订单

**作为桃子，我希望替私聊订餐的邻居记单并回传订单卡；作为顾客，我希望确认关联后能找到这笔订单，以后自行订餐。**

对应 PRD 5.4。桃子记录顾客、日期、午晚餐、份数和收餐信息，代下后回传订单卡。顾客发起关联，桃子确认一次后开放本人的详情访问。

完成条件：确认前，卡片接收人不能凭卡片查看订单详情；转发给其他人也不授予访问权；不能仅凭同名或同手机号自动归属；关联后仍需联系桃子修改代下单。普通自助下单不因此增加审核。按 AC-07、AC-21 验收，信息选填规则同 AC-20。

误关联纠正、重复顾客记录见 Q5；代下容量边界见 Q6。

### US-07 在允许范围内修改或取消订单

**作为顾客，我希望在截止前自行调整自己下的单餐；超出自助范围时，能清楚知道需要联系桃子。**

对应 PRD 5.4、5.5。顾客直接创建的单餐在截止前可改份数或取消，增加份数仍受余量限制；代下单、连续订餐及截止后的单餐联系桃子。

完成条件：前后端均执行同一权限规则；桃子修改自助订单不改变其创建来源；取消或减量同步更新有效份数和配送清单；修改地址簿不改写既有订单地址。按 AC-09 验收。

连续剩余餐次的调整操作见 Q4；已截止、已送达或已记录收款订单的其他更正见 Q6。已付款停餐退款按 US-11，不能用删除记录代替更正。

### US-08 申请、审核并启用连续订餐

**作为顾客，我希望一次约定连续多天的午晚餐；作为桃子，我希望审核并确认微信付款后，再把这些份数纳入供餐安排。**

对应 PRD 5.5。顾客申请或桃子代建时，选择开始日期、4—90 个连续天、午餐或晚餐或两餐，以及所选每餐 1—20 的整数份数。

1. 提交前核对起止日期、分餐份数、收餐地址和金额计算，手机号可留空。
2. 桃子通过后进入待付款；拒接时填写简短说明，可复制私聊给顾客。
3. 顾客微信付款后，由桃子明确标记收到并生效；未来菜单可在之后公布。

完成条件：审核通过、截图划掉和菜单公布都不自动使申请生效；待审核、待付款、已拒接不计入有效份数；生效后保留份数，公布菜单不重复计数；到期不自动续订；拒接原因不发群。按 AC-08、AC-18、AC-19、AC-20 验收。

开始日期、已知不供餐日期、重复订单、容量冲突和后续调整见 Q4；不能把尚未解决的冲突默认当成允许超量。

### US-09 按准确份数制作并完成配送

**作为桃子，我希望直接看到某餐该做多少份、分别送给谁，以便不用重新从聊天记录汇总。**

对应 PRD 5.6。按餐次汇总有效自助单、代下单和生效连续订餐，另计自家用餐份数；按小区和楼栋查看配送清单，逐单或按组标记送达。

完成条件：各种顾客份数各计一次；自家只计制作，不进入顾客配送和收款；取消或停止的份数退出清单；逐单和按组更新进度一致；送达不自动表示收款，普通未付款订单也可配送完成。按 AC-13 验收。

容量、自家份数入口、分组及未留手机号且微信联系不上时的处理见 Q6。失联如何处理尚未确定，不预设放门口、取消或视为送达。

### US-10 核对微信收款并跟进待核项

**作为桃子，我希望一次处理多张微信收款截图，能看清哪些已经核对、哪些还需人工处理。**

对应 PRD 5.7。

1. 选择多张截图，逐张读取姓名、金额和时间并匹配订单。
2. 唯一匹配项自动划掉并显示依据；多候选或无匹配项留待核对。
3. 完全识别失败时看到失败提示和原截图，可以重新识别，或人工核对后直接划掉，无须补字段或理由。
4. 已划掉项可以恢复，能区分系统和人工处理；未收到普通订单款项时，由桃子主动发送提醒。

完成条件：每张图的结果独立可查；划掉仅表示核对完成，不表示平台验证到账；无明确匹配不擅自关联订单，连续订餐不因此自动生效；发出提醒不自动记为已收款。按 AC-14、AC-16、AC-22 验收。

### US-11 停做某餐并跟进退款确认

**作为桃子，我希望停做某餐时知道要通知谁、退出多少制作份数和退多少钱；作为顾客，我希望核对并确认自己收到的退款。**

对应 PRD 5.8。

1. 停餐确认前查看受影响顾客、份数和预计应退金额。
2. 确认后取消该餐履约、关闭普通报名入口，生成公告和已付款退款清单；桃子主动发群并在微信退款。
3. 顾客核对金额，收到后确认；已付款连续订餐退款若误点确认，联系桃子恢复待确认，保留原确认和更正记录。

完成条件：未付款取消不生成退款项；应退金额按取消份数乘订单单价；连续订餐只处理受影响餐次，其他餐继续；待确认不证明资金未到账；更正不重复生成退款任务。按 AC-12、AC-17、AC-23 验收。

连续剩余餐次批量调整和其他已履约、已收款更正分别见 Q4、Q6。

## 3. 联合验收

| 路径 | 串联故事 | 要检查的整体结果 |
| --- | --- | --- |
| 排好一周并公布一餐 | US-01 → US-02 → US-03 → US-04 | 七天安排可回看；逐餐去汤正确；确认与公布分开；公布餐次锁定 |
| 自助与代下后的日常供餐 | US-05／US-06 → US-07 → US-09 → US-10 | 访问归属正确，订单、制作、配送份数一致，普通单可先送后付 |
| 连续订餐停餐退款 | US-08 → US-09 → US-11 | 付款并标记后生效、份数不重复，停一餐只影响该餐，可纠正退款确认 |

逐条通过 PRD 的 AC-01～23，再完成上述联合路径。真实试用另按 PRD 第 6 节记录效果，技术测试通过不能替代桃子实际使用。
