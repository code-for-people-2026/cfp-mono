### 1.1 本轮界面验收

- 2026-09-24 用户明确要求菜名不换行：菜品池、录入预览、菜单表、选菜详情、候选和首页菜名均单行显示，超出容器以省略号收尾；H5 使用原生 `title` 提供完整内容。检查页与历史页不再因长菜名增高菜格。原始菜名、输入及复制文字不截断，不改变 60 字符校验。
- 2026-09-21 用户明确要求不擅自添加描述性文案。使用已确认原型文案及必要的功能、状态和错误说明，不自行增加标语、欢迎语或重复状态卡。后续明确要求删除编辑顶部及复制页的旧微信消息/通知邻居解释文字，不用其他提示替代。
- 复制页按最新截图反馈去掉重复标题、黄色操作说明框、品牌行以及“已保存的一餐／复制后仍可修改”页脚；正常状态保留顶栏“复制菜单”、日期和午晚餐选择、分别可编辑及复制的“接龙说明”和“填写示例”、返回操作，以及固定底部“排菜单／菜品池／历史”导航。不提供“继续编辑”捷径，需编辑时返回本周菜单进入。底部留白须防止导航遮挡内容；未保存保护、读取／复制失败及操作结果仍在发生时显示，导航继续遵守未保存与未知写入保护。
- 区分本周入口和菜单编辑页，按工程原型提供进入与返回。手机内容区同时展示两天，横向查看七天；拖动或滚动结束按日期列对齐，不停在裁切半列位置，周六/周日末尾仍完整可达。编辑、检查及历史共用此行为；午晚餐分组及“荤菜／全部”切换。采用工程版字号、48px 菜格及右侧纵排换菜按钮，不沿用客户版的三列小字。跳过餐、去汤、零数量分类、长菜名及允许的最大菜量须正确展示和操作；滚动内容与底部操作区分开，避免遮挡。
- 点中具体日期、餐次的一道菜后，“换一道”进入独立候选页，“自己选”进入可搜索的合法同类菜选择状态。确认替换才改变目标菜位；返回、取消和切换目标保留其他草稿调整。单餐做汤安排从本周入口可达。
- 2026-09-21 用户截图再次指出编辑页仍未忠实实现。编辑页按工程版 `MenuEditor` 的结构呈现：菜单表、紧凑选菜卡；按 2026-09-22 试用反馈，固定底部按钮使用“确认菜单”，不附餐数或勾选图标。日期使用原型短格式，选菜卡使用“周一午饭 · 荤菜”等原型文案，不加“当前选择”。实际横向滚动容器隐藏滚动条，同时保留触摸、鼠标和键盘操作。有菜的选中位置只显示“换一道／自己选”；按后续业务反馈，去汤／恢复移至已保存菜单的具体餐次界面，编辑页不提供该操作。文字复制保留在既有保存后路径；编辑页不再堆叠“预览本餐文字／保存调整／修改周设置／取消编辑”。返回与离开仍保护草稿，最终写入仍通过检查页。不得把这些已发现的偏差列为允许的产品差异。
- 2026-09-22 试用调整：餐次和菜量作为生成流程上一步，不设独立“周设置”入口。流程为“安排餐次和菜量 → 调整菜单 → 检查保存”；编辑页标题为“调整菜单”，左上角“返回安排”，已有菜单可直接进入调整。返回安排保留当前菜单及换菜结果；餐次和菜量与当前菜单生成条件相同时提供“继续调整菜单”，不重生成，条件有变时才提供“重新生成菜单”。覆盖整周调整的提醒及取消／失败保留规则继续适用。本轮实现仍待用户验收。
- 固定入口为“排菜单／菜品池／历史”。空菜池引导录入自己的菜，再设置并生成；已有菜池可直接排菜。离开有修改页面须确认，取消保留输入；批量录入及写入结果未知时的保护不得因导航失效。重新进入历史须读取最新保存记录。
- 编辑后进入只读横向菜单表检查，进入检查页不写入。最终点击“保存本周菜单”一次原子保存并确认；此前保持未保存状态，返回继续编辑不丢草稿。成功后回到已保存周首页，提供所选餐次的复制入口及次要的整周调整入口，沿用独立的选餐、预览、主动复制状态。
- 历史直接显示已保存周的同款只读横向表，左右切换已保存周；提供共用的“荤菜／全部”筛选，默认全部，保持水平位置及只读状态，复制仍使用完整菜单；保持历史导航选中状态，支持更早保存记录及重新进入刷新。取消客户版的十四张纵向餐次卡作为总览呈现。
- 本轮不引入家庭人数、预设图片菜库、复制到下周、空的“我的”页或新接口及数据表。Q1～Q3 和现有菜池、菜单数据保持不变。

## 2. 业务决定与实现默认值

### 2.1 已确认的三个业务决定

2026-09-20 用户在逐项了解具体情境后回复“1a，2a，3a”。下列规则已确认，Q 编号继续用于追溯。

| 编号 / 选择 | 具体场景 | 正式规则 |
| --- | --- | --- |
| Q1 / 1A | 已排好两荤一素一汤，并换过菜、去过某餐的汤，现在想改成三荤一素一汤 | 先提醒将覆盖整周换菜、逐餐去汤等调整；确认才重生成。取消或失败保留原编辑及服务器记录；成功后检查并显式保存才覆盖已保存菜单 |
| Q2 / 2A | 一餐需要两道荤菜，但菜池只有一道可用荤菜 | 列明分类、所需和现有数量，整次不生成。补菜或改结构后重试，不生成或保存缺位菜单；足以一餐但不足整周不重复时仍允许跨餐重用 |
| Q3 / 3A | 周三午餐已发群，后来买不到清蒸鱼，想换成黄焖鸡 | 确认、复制或发群后均可继续编辑、保存并重新复制；由桃子自行通知邻居，旧微信文字不自动更新；不显示额外解释提示。没有公布、锁定或解锁动作 |

上述业务选择已同步 PRD、用户故事、数据模型与接口。它们不再是开发前待答项；实现、性能和真实上线条件仍须验证。

### 2.2 本稿采用的最小实现约定

这些是本次补规格提出的交互和工程默认值，可以在评审时调整，不冒充桃子已经验证的习惯。

- 新周独立设置，不自动生成或复制上周菜品，也不新增“常用模板”管理。页面可以保留当前尚未提交的表单；自动继承跨周设置留到试用后。
- “换一道”进入候选页，在本餐合法候选中随机建议；“自己选”可搜索并按名称查看合法同类菜。候选排除当前菜，确认替换才更新草稿，不维护跨次候选轮换历史。
- 去汤针对该餐全部汤位。恢复时优先使用隐藏的原汤；若其中有已停用或改类菜，提示重新选择可用汤，凑齐本周汤数量后一次恢复，取消则维持去汤。汤池仍不足时不恢复，不改其他菜。
- 实际做饭的临时去汤从已保存周的本周入口进入单餐调整，明确日期和午／晚餐，默认所选周内今天的已安排餐，否则该周首个已安排餐。选择目标、去汤／恢复后显式保存本餐调整，不进入整周编辑／确认。只从保存快照开始，有整周／设置草稿时按已有保护处理，不混入或丢弃；未保存周、跳过餐、周结构无汤时不能执行去汤。复用版本校验和幂等周保存，除目标餐汤状态及恢复所需汤内容外其他菜单内容不变；使用普通保存语义清原确认，不自动确认整周。
- 2026-09-22 最新批准将接龙说明与填写示例分开输入、分开复制。说明默认只有标题“月.日号星期X午餐／晚餐预定接龙（30元）”及按荤、素、汤顺序连续编号的菜名，不包含“#接龙”、“例”、示例或真实报名。示例按餐次默认为 `1份午餐` 或 `1份晚餐`。两项都允许直接编辑；30元仅为默认文字，不建设独立定价设置，也不将分享修改写回菜单。
- 工程版的确认页先检查菜单，仍属未保存草稿；最终“保存本周菜单”一次保存并确认同一内容，成功才进入已保存状态。进入或取消编辑不改服务器状态；普通保存编辑结果清除原确认时间。按用户最新反馈，不再展示旧微信消息/通知邻居的解释文字，无需记录是否实际发送。
- 只分享服务器已保存版本。存在未保存修改时阻止生成新的分享预览并提示先保存或放弃修改；不默认替桃子丢弃草稿。无未保存修改时重新读取已保存周再生成餐次文字，读取失败提示重试，不要求额外“发送确认”。

## 3. 用户场景与优先级

所有下列场景均属于首版。P1 指先完成核心闭环，P2 指随后完成交付闭环，不表示可以省略分享。

### P1：建立菜品池（US-01，AC-01）

Given 桃子粘贴每行一个菜名，When 系统形成分类预览，Then 菜品尚未进入菜池；桃子可循环纠正分类、返回改名后确认。

Given 桃子确认一批无重复的菜，When 保存成功，Then 显示本次新增数量；超时后重试同一请求不新增第二批。批内或菜池已有同名菜时列明名称，整批不写入，桃子修改后以新请求提交；已停用同名菜提示去维护中恢复。

Given 某菜已用于保存的周菜单，When 桃子改名、改类或停用该菜，Then 历史菜单的名称和分类不变；后续生成、换入或恢复汤重新检查当前可用性。

### P1：生成一周（US-02，AC-02、AC-04）

Given 本周两荤一素一汤且下周三荤一素一汤，When 分别生成，Then 每周遵守各自结构，每天午晚餐按日期组织，跳过餐次不出现菜品。

Given 一餐所需分类均足够，When 生成整周，Then 同餐无重复；优先整周未用菜，再选择本周较久未出现的菜。整周菜不够时允许跨餐重用，不混用荤、素、汤凑数。连一餐都不够时返回具体缺少分类及所需/现有数量，整次不生成，补菜或改结构后才能重试。

Given 已有菜单且换过菜，When 桃子返回安排且餐次、菜量与当前菜单的生成条件相同，再点击“继续调整菜单”，Then 回到原菜单并保留换菜结果，不调用重新生成，也不写入服务器。

Given 已有菜单且换过菜、去过汤，When 桃子返回安排修改餐次或菜量并点击“重新生成菜单”，Then 系统提示重排会覆盖这些整周调整，确认才开始生成；取消或生成失败保留原编辑和服务器菜单，成功仅更新预览，显式保存才覆盖原记录。

### P1：局部调整并保存（US-03a／b／c，AC-03、AC-05）

Given 已有可编辑菜单，When 随机或手选换掉一个菜位，Then 只该位置改变；若没有合法候选，提示并保留原菜。

Given 桃子进入整周修改菜单，When 选中汤菜，Then 可替换汤菜但没有去汤／恢复按钮；“本餐做汤／本餐不做汤”供餐决定在已保存菜单的具体餐次界面操作，恢复行为按 2.2。

Given 已保存且可已确认／复制的周菜单，When 到周三实际做午饭时从本周入口直接选择周三午餐、去掉汤、保存本餐调整，Then 不经整周编辑或确认，仅该餐汤状态改变，其他菜、餐次及周结构完全不变；成功后重开和重新复制该餐文字均无汤，恢复后保存则重新含汤。取消不写入；失败不显示成功且保留调整；未知结果重试沿用同一请求，冲突不得覆盖新版本。提前删除未来餐的测试不能替代本场景。

Given 两台设备都读到 version=3，When 第一台保存得到4、第二台仍按3保存，Then 第二台收到版本冲突，保留本地草稿并提示重新读取；不能静默覆盖第一台。

Given 桃子保存或确认，When 网络失败或服务失败，Then 不显示已保存，原完整记录不变；当提交已成功但响应丢失，原请求安全重试返回原结果。确认与内容保存一次完成，不能确认旧版却展示未保存新版。

Given 读取已确认菜单，When 进入编辑后取消，Then 原内容和确认时间不变；普通保存编辑结果清除确认时间，保存并确认才对新内容设确认时间。不得因已确认或复制过而拒绝合法编辑。

### P2：回看并复制某餐（US-12，AC-24）

Given 桃子重新登录同一微信账号或换设备，When 选择一个已保存周，Then 看见原保存菜单及去汤结果；本地临时预览不是跨设备保存内容。

2026-09-22 首页试用调整：已保存周首页显示所选一餐的实际菜名，荤、素、汤分行，显示日期并支持午晚餐切换；默认所选周今天首个已安排餐，否则该周首个已安排餐，实际日期不是今天时不标“今天”。移除首页大统计卡、搭配卡和重复保存状态，周范围旁保留小状态，整周调整为次要入口，保存成功反馈短暂出现。预览使用 `saved`，不将未保存草稿显示为可复制内容；全新未保存菜单不显示复制预览，仍继续调整并保存。本轮待用户试用验收。

主动作随所选餐次显示“复制午餐菜单”或“复制晚餐菜单”，保持同一日期和餐次进入独立的“复制菜单”状态，仍重新读取最新保存内容并执行草稿保护，核对后由用户主动复制；可返回周菜单，或通过底部导航进入排菜单、菜品池、历史。编辑从本周入口进入，不在复制页另设“继续编辑”。逐餐入口复用同一状态，不能让下一步只藏在日期展开项中。

Given 选择已保存的某餐，When 生成文字，Then 分别生成上述格式的接龙说明和填写示例；说明使用实际日期、星期、午晚餐及完整菜名，不附加“#接龙”、“例”或真实报名，示例按午晚餐生成。去掉的汤不出现，分类为空或去汤后编号仍连续；跳过的餐次没有复制入口。

Given 桃子修改接龙说明的价格、菜名或独立的填写示例，When 点击对应复制动作，Then 剪贴板内容与该字段当前文字完全一致，不混入另一字段，编辑不写回菜单。空白只禁用对应复制，失败保留输入；说明和示例分别记录未复制的修改，复制一项不解除另一项的保护。切餐、退出或调整汤重新生成前保护任一项未复制修改，取消保留两项输入；没有未复制修改时返回不再提示放弃。

Given 桃子主动复制说明或示例，When 平台报告成功，Then 短暂提示该项已复制，并指明粘贴到微信接龙的说明或示例栏目；失败保留输入并允许重试。系统不声称微信已创建接龙、参与接龙或发送消息，不产生订单，也不承诺向聊天框粘贴整段文字自动形成接龙。复制或发群后仍可编辑，保存后生成新文字重新复制，由桃子自行通知邻居，原微信消息不变；页面不再展示相关解释提示。本轮只作本地验证，微信创建与参与接龙由桃子本人实测，未取得实测结果前不得写成已经成功或完成验收。

### 共同保障（全部故事，AC-25）

Given 未获桃子权限的微信用户，When 请求登录或直接请求任何内部接口，Then 不创建经营账号、不返回菜池或菜单。修改客户端角色、对象 ID 或请求体不能取得权限。

Given 已有真实保存记录，When 运行恢复演练，Then 在隔离库找回菜池、周菜单快照和账号关联；备份文件存在不等于演练通过。退出删除必须覆盖在线数据、会话、含数据回执和备份，验证后才能宣称完成。

## 5. 工程约束和异常反馈

- 日期按 `Asia/Shanghai` 解释，API 使用 ISO 日期，不用毫秒时间戳代表餐期。`2026-09-21` 为周一，目标周到 `2026-09-27`，每天先午后晚。日历运算必须跨月、跨年及闰日正确。
- 每类数量先设0～10、总数量1～20；每次最多200道、菜池最多1000道（含停用）、单名1～60个 Unicode 字符、请求128 KiB。这些是初始保护值，非已调研出的经营规模；达到限额说明原因，不截断。实现前可按实际菜池调整并同步契约。
- 所有写入先做输入和权限校验，再使用事务；错误返回动作相关提示，不显示原始数据库或微信响应。详情见契约错误表。
- 本地未保存草稿只保留在当前页面内存，不承诺强制退出后恢复；小程序被系统杀掉后只能恢复服务器已保存内容。本周入口的状态标记反映“未保存”；编辑及检查页按工程原型使用确认／保存动作和“确认后保存本周菜单”，不另加常驻解释文字。返回本周入口保留草稿；离开当前周、切换业务入口或关闭页面时继续执行未保存保护，失败和写入结果未知仍显示必要的恢复提示。
- 不把 UI 隐藏、H5 mock、剪贴板成功或数据库迁移脚本存在当作权限、真机发送、跨设备保存或恢复完成的证据。

## 6. 完成定义

自动化必须覆盖正常路径之外的同餐重复、跨周日期、去汤无旁路修改、历史快照、并发写入、重复提交和跨账号读取。具体用例在 [contracts/README.md](contracts/README.md) 与 [quickstart.md](quickstart.md)。

试用目标仍是桃子实际用一周后，确认的菜单能直接照着做、分享无需重抄。性能初始测试预算与恢复建议见 TECH-SPEC，不将未测量的数值写成实测结论。

Q1～Q3 业务决定已完成；实现任务完成、仓库门禁通过、微信真机与恢复删除演练分别取得证据后，才能说具备首版交付条件。原型调整或本地试用通过不替代这些交付证据。
