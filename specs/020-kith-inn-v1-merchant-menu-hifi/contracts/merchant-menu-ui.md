# UI 行为契约：商家本周菜单

## 工作周契约

- 周一至周四进入时展示当前工作周；周五至周日展示下一工作周。
- 所有业务日期按上海时区计算；五日范围固定为周一至周五。
- 默认选择展示周中第一个尚未过去的工作日，未来周选择周一。
- 上一周/下一周每次移动 7 个日历日；快速切换只接受最后一次加载结果。
- 已有数据刷新时继续展示；首次失败显示可重试错误态。

## 日期条与餐次契约

- 日期条始终有五项，点击日期只切换本地所选日。
- 每日固定渲染午餐和晚餐；缺失餐次不伪造持久化记录。
- 菜单正文只使用餐次保存的 `nameSnapshot` 与 `mainIngredientSnapshot`。
- 空价格显示“商家默认价”；空截止时间显示“未设置截止时间”。
- 状态文案固定为“未排菜单 / 待设置 / 待开放 / 预订中 / 已截止 / 已关闭”。
- `draft` 截止时间为空或已过显示“待设置”，未来截止时间显示“待开放”；价格为空合法并显示商家默认价。
- `open`（包括截止后）和 `closed` 前后端只读；仅截止时间已过的 `draft` 仍可修改菜单。

## 生成与覆盖契约

- 单餐生成只发送一个缺失目标。
- 整周首次生成发送十个缺失目标；补齐只发送当前缺失目标。
- 已有菜单不进入补齐目标。
- 重新生成只包含可编辑草稿，并在写入前展示日期和午晚餐目标。
- 覆盖确认展示响应中的已有目标，确认后提交最初的完整目标；切周或目标状态变化使旧确认失效。
- 覆盖取消不改变菜单、周或日期选择；确认后只合并返回目标。
- 菜品池不足不写入不完整菜单，显示分类缺口并提供菜品库入口。
- 放宽规则时菜单视为成功，同时显示可读说明；整周生成只显示周级聚合说明。
- 非菜品池错误可能发生在逐餐次持久化中途，失败后必须重载当前周对齐真实结果。
- 生成请求捕获目标周和 mutation revision；切周后的延迟成功或失败响应不得合并餐次、覆盖提示或清除新周确认状态，失败重载也必须绑定原目标周。
- 业务服务预检查不能替代持久化保护；CMS/Payload 提交菜单变更时必须依据最新 `orderStatus` 原子拒绝 `open` / `closed`，并把锁定冲突稳定传回前端。

## 换菜契约

- “换一道”先显示当前五道菜，用户只选择要换掉的菜。
- 请求只提交目标餐次和原菜标识；不展示伪造候选。
- 成功只替换目标餐次返回快照；无候选时原菜单不变。
- 只锁定当前餐次换菜，其他日期仍可浏览。
- 换菜同样绑定目标周和 mutation revision；切周后的旧响应不改变当前餐次、提示或 sheet 状态。

## 预订衔接契约

- “设置价格与截止时间”携带当前周起点和目标餐次进入现有配置页。
- 配置页读取日期上下文后自动加载餐次，不要求从空输入开始。
- 返回菜单页刷新当前周并保留所选日期。
- 底部入口按缺失目标、草稿配置/开放、查看预订与分享的顺序选择；已有开放餐次不覆盖仍需补齐的更高优先级动作。
- 不在菜单页复制完整表单；价格留空表示使用商家默认价。

## 呈现契约

- 视觉基线为 `docs/kith-inn-v1/design/merchant-menu-hifi-v0.2.png` 和共享 HTML；Prompt 不属于仓库产物。
- 354×786 下无横向溢出，卡片内容可纵向滚动，固定 CTA 与导航不遮挡最后一个餐次。
- 复用“今日 / 菜品 / 菜单 / 订单”导航并激活“菜单”；不伪造系统胶囊。
