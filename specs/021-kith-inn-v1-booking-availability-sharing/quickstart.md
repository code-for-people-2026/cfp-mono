# Quickstart: 营业预订与分享定位验收

## 自动化

```bash
pnpm --filter @cfp/kith-inn-v1-shared test
pnpm --filter @cfp/kith-inn-v1-be test
pnpm --filter @cfp/cms test
pnpm --filter @cfp/kith-inn-v1-fe test
pnpm verify
pnpm --filter @cfp/kith-inn-v1-fe exec playwright test --grep '按日期生成|紧凑历史|默认价应用、个别改价并批量开放完整工作周'
```

## 关键场景

1. 修改默认价，开放餐次后再改默认价，确认已开放餐次价格不变。
2. 混合选择有效和无效餐次批量开放，确认逐项结果及重复点击防重。
3. 标记整天/单餐打烊并取消；确认未设置隐藏、打烊可见，已有订单时写入被阻止。
4. 分别分享某天和某餐，确认微信卡片 payload 及公开 `batch` 路径。
5. 375×812 检查配置、部分失败、成功详情、历史、停止和归档状态；H5 自动化不得冒充真机分享验收。

## 三分钟真人可用性计时

T033 不得用 Playwright 执行时长替代。准备含一周可配置餐次的固定账号，由真人在 Page 4 数据加载完成后开始计时，依次保存默认价、对一个餐次改价、选择并批量开放一周餐次；页面显示全部逐项成功时停止。记录参与者、设备、起止时间、总时长和失败/求助点；只有总时长不超过 3 分钟才通过 SC-001。

## 微信真机 smoke

截至 2026-07-27 未执行，T027 保持未勾选。当前环境已安装微信开发者工具 Stable v2.01.2510290，但处于未登录/游客状态，打开的还是另一工作树的旧构建；CLI 工具服务端口未启用。登录扫码、聊天卡片和真实设备安全区都需要外部会话，且不应未经确认开启工具服务端口。H5 的“复制入口”不作为原生小程序卡片分享证据。

执行前必须：

1. 记录待验收 commit SHA，并确认工作树干净。
2. 确认后端采用微信云托管/云开发，或其 HTTPS 域名已加入该 AppID 的 request 合法域名；直连域名必须有有效证书并满足 ICP 备案等微信门禁。记录配置与验证结果，域名门禁失败不得归因于分享构建。
3. 使用上述真机可访问且已获准的 HTTPS 后端执行 `BE_BASE_URL=https://<wechat-approved-host> pnpm --filter @cfp/kith-inn-v1-fe build:weapp`。
4. 在微信开发者工具中加载当前工作树的 `apps/kith-inn-v1-fe/dist`，记录 SHA、构建时间、AppID 和后端地址；不得沿用另一工作树或旧构建。
5. 完成开发者工具登录和真机调试连接；启用 CLI 工具服务端口仍需发起人明确确认。

具备真机后需逐项记录：

1. 分别分享某天与某餐，确认聊天中出现原生小程序卡片，标题和目标准确。
2. 顾客点击卡片后进入目标日期/餐次，路径中的 `date`/`occasion` 与目标一致；当前兼容顾客页的 batch 访问边界不得作为 FR-011/D002 已完成的证据。
3. 必须停止目标餐次后再次打开同一卡片，确认对应餐次按最新状态变为不可预订，而不是继续展示创建时快照。
4. 另行停用分享入口并再次打开同一卡片，确认入口关闭状态；此步骤不得替代第 3 步的餐次实时变化验证。
5. iPhone 刘海/底部安全区与 Android 常见尺寸下，商家 Page 4 的配置、成功详情和历史状态无内容遮挡，主动作可触达。

顾客直接打开应用后的商家选择、同商家全部实时餐次浏览，以及在顾客 API/UI 中独立展示打烊原因，仍属于后续顾客端 D001/D002，不是 T027 的通过条件；这些原需求保持未完成，不改写成兼容期 batch 白名单行为。
