# 年龄复核与重新核验

年龄信息出现冲突或已有未成年记录时，聊天、上传等能力保持暂停，隐私与反馈入口继续可用。人工处理可选择开放一次新的本人核验流程、维持限制，或由系统管理员基于线下核实的材料直接恢复年龄能力。直接恢复只表示人工 assurance，不冒充身份供应商、不声明姓名证件匹配，也不解除其他案件的内容限制。

## 用户操作

1. 在年龄提示窗口选择「申请年龄复核」或「年龄核验帮助」。帮助与反馈中的「年龄核验与账号恢复」显示当前状态、受理编号和处理回复；已有待处理事项不会重复创建。
2. 待受理、处理中或复核中，由工作人员处理。用户可以刷新查看结果，不需要在反馈中提供姓名、证件号、证件照片或聊天原文。
3. 管理员允许重新核验后，选择「返回并开始重新核验」，回到聊天页的年龄窗口。阅读核验说明并单独同意后，在专用表单提交本人信息。
4. 选择重新核验时，只有新的供应商结果确认成年且账号、批准及隐私状态仍有效，才解除年龄限制。管理员直接恢复时，用户不需要重复提交身份表单；系统按当前年龄有效期给该人工结论 30 天有效期。到期或说明版本变更后，历史人工决定只作为处理记录展示，当前能力不可用，用户须重新申请普通续期复核；该续期不是拒绝申诉，可由原管理员按当前案件重新核实，审核通过前不自动延长，也不能授权新的风险。未成年、未知、服务异常、超时、取消或新的风险不会默认放行。
5. 维持限制时显示具体回复；再次提出复核保留原案件关系，由不同管理员处理。旧版本已受限但没有工单的账号也可从同一入口申请。

普通身份信息匹配不等于人脸或操作者本人活体认证；本流程不新增人脸采集，也不扩大现有供应商能力。

## 管理员操作

进入 Payload 后台「内容安全运营 → 审核案件 → 年龄限制复核」，打开当前案件并「领取并受理」。查看年龄复核来源和必要记录后，填写理由及向本人反馈的说明，选择：

- 「批准发起一次新的本人核验」：用户仍受限，下一步由用户通过专用表单重新核验。
- 「维持年龄限制」：继续限制，并向用户说明处理结果及后续路径。
- 「直接解除年龄限制」：系统管理员填写人工核实理由和用户回复后，事务内结案、审计并恢复当前账号年龄能力。存储记录使用 `manual_administrator_assurance` 与专用人工来源，不写成供应商匹配结果，也不新增物理字段或伪造同意/回执；公开状态中的 `assurance` 保持 `null`，并用复核元数据标识人工决定，保证 0.8.1 客户端仍可解析完整状态。

年龄决定需要系统管理员权限、本人领取和当前案件修订号。普通审核员不能批准；旧周期案件不能重新影响当前周期；申诉不能由原决定人再次作出结论。通用「结案」「解除生成限制」不替代年龄复核。

自动风险、供应商新未成年结果和本人申请分别记录来源及审计执行者。证据只保存固定的最小说明，不复制原始聊天、姓名证件或供应商完整响应。审批及其审计采用现有 Payload 事务；不开放原始记录的直接编辑。

## 核验与兼容性

实现复用既有年龄记录和审核案件，不增加物理数据库字段。批准与当前案件版本和当前周期引用绑定；核验提交先把挑战消费为 `pending`，在同一事务内复核身份绑定、隐私状态、租约、年龄状态、更新时间和批准版本，之后才允许供应商调用；核验结果落库前再次原子核对。直接恢复会作废未完成挑战，晚到的供应商响应不能覆盖人工决定。新风险、新未成年结果或新的未满 14 岁申报会使旧授权失效并创建新周期；即使原案件仍在待受理、处理中或复核中，旧修订号也不能恢复或覆盖新风险。用户重复申请只复用当前未结案件或当前批准，维持后的申诉以最新决定为父案，不改绑旧未结案件。取消使已发出的核验挑战失效。前端对旧响应缺少复核字段保留安全降级。

回归使用虚构账号、固定合成说明和注入的供应商结果，在临时 SQLite 中验证完整闭环、并发决策、旧批准重放、取消、未成年结果、独立复核和数据权利。隔离测试不等于真实证件核验或手机验收；正式发布使用仓库构建、发布及自动保留流程。
