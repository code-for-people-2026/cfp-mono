## 发现并修正的接入问题

ADK 的 Google Schema 用字符串表达 `minLength` / `maxLength` 等约束。DeepSeek 要求标准 JSON Schema 的整数，最初拒绝请求并返回 HTTP 400。模型适配层现转换类型名与这些数字约束；回归测试使用真实 ADK `FunctionTool` 生成的声明，避免只测试手写 Schema。

没有为迁就新模型静默改动吉祥话指令，提示词版本仍为 `greeting-v1`。纯色图误识别保留为未解决的模型质量问题；应扩充有人工标注的图片评测集，再决定提示词或模型变更，不能仅以 HTTP 成功、保存成功作为通过标准。

## 密钥与数据边界

- 平台凭证只在本项目被 Git 忽略的 `.env.local`，文件权限为 `600`。
- BYOK 凭证只在当次请求中使用；测试凭证与真实凭证均检查过数据库未保存。
- 检查了真实评测库与开发库（含存在的 WAL 文件），未发现模型密钥。
- 检查了 53 个可提交源文件和 66 个前端构建文件，未发现模型密钥。
- 外部测试使用单独身份与令牌，测试结束后撤销该 MCP 令牌。
- 测试调用会消耗用户提供的 DeepSeek 账户额度；未充值、订阅或更改账户设置。

## 验证脚本的冷启动边界

曾遇到重启读取子进程在 45 秒时超时，但单独运行同一个读取脚本可以完成全部断言。分段测量发现本机 Payload、ADK 与配置冷导入约 35 秒；这不是存储丢失。重启读取现使用生产模式避免重复同步 schema，并把测试启动预算调整为 120 秒，原有持久化断言保持不变。修正后 11 组集成验证全部通过。
