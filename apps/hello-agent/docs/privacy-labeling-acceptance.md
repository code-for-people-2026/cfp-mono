## 实际数据流

| 数据/入口 | 处理及接收方 | 保存与删除 |
| --- | --- | --- |
| 文字、练习回传 | REST/AG-UI → Payload轮次 → DeepSeek生成/安全审核；表单按原题目服务端重建 | greetings；删除覆盖文字、作品及失败轮次 |
| 历史、摘要 | sessions.memory + 近期轮次 → 平台/BYOK模型；MCP只在单独授权后读取 | 摘要与完整历史分别保存，两者一并删除 |
| 图片 | 当前上传暂停；后续接通审核后才可压缩JPEG/去EXIF定位/保留已有有效AIGC并存入私有存储 | media、OSS对象、同身份无数据库引用的OSS对象一起清理；未发送但已上传图片也包括 |
| 执行轨迹 | ADK事件/工具调用 → adk-sessions；不持久化图片字节、隐藏思考、原始报错 | 与身份关联清理；内部快照混有后台知识资料，不直接自助导出，本人数据可申请核验副本 |
| BYOK密钥 | 本次请求内存 → DeepSeek；发送后前端清空 | 不写业务库；日志禁止请求头/正文 |
| Cookie/小程序/MCP | 随机身份；不是wx.login；客户端持令牌，服务端保存摘要 | Cookie/设备30天，MCP7天；撤回/变更授权撤销MCP，退出/删除撤销全部；维护任务清除过期摘要 |
| 恢复码 | 随机256位秘密，只保存摘要；找回后撤销旧连接 | 自行保管；可轮换；删除后失效；无凭证及恢复码需运营核验，不承诺能找回 |
| 同意/撤回 | privacy-profiles记录版本、范围、接收方、时间及当时政策快照 | 删除清除同意内容，保留最小防回写墓碑；备份处置确认前不盲删删除凭据 |
| 在线反馈/审核案件 | 本版本未接入，不接收在线提交 | 帮助页提供政策联系渠道；#383 后续接入时须同时实现案件导出、证据删除及有依据的留存告知 |
| 广告 | 仅配置启用时用微信激励广告；无聊天正文参数 | 观看资格在会话记忆中，随删除清理 |
| 语音 | #381 的 WechatSI / 浏览器识别先产生草稿，用户发送后交给平台 | 平台不保存录音；识别供应商侧的处理与留存仍须发布前核实 |
| 访问日志、回退备份 | 部署反代可能记录IP/时间/路径/状态；旧发布备份可能包含数据 | 不冒称按钮逐条抹除；期限/轮转/快照/版本桶由公司核实及配置 |

生成插画PNG和独立HTML按已存作品即时渲染，没有额外持久化文件；删除原轮次后鉴权读取失败。测试生成的样例文件属于隔离验收材料，不含真实聊天。

## 授权及权利接口

- 无需身份即可 GET `/api/hello/legal`（结构化政策）和 `/api/hello/legal/page`（可保存HTML）。小程序和H5主入口都可打开“隐私与数据”。
- 同意四项均不预选：基础保存与协议、模型传输、安全/情绪/图片敏感处理、外部读取。新版本/过期/撤回均拒绝继续生成与上传。敏感文本规则只是辅助识别，不宣称能够识别一切敏感内容；已有敏感历史撤回后不能继续送模型。
- 外部授权记录实际客户端/模型接收方、联系方式、处理地域和政策链接；每次更新授权撤销旧MCP令牌。用户填写不代替公司的跨境法律手续或供应商评估。
- GET `/api/hello/privacy` 和 `/privacy/export`；POST `/privacy/consent`、`/withdraw`、`/recovery-code`、`/delete`、`/logout`；POST `/api/hello/privacy-recover`。
- 浏览器写入校验精确Origin；原生令牌在无Origin请求下工作；外部Bearer不能代替本人同意、恢复码管理或删除。
- 删除须提交完整确认短语。服务端只从鉴权身份确定owner，不接受指定其他owner。先冻结、等在途执行锁结束、记录独立删除清单、清对象及数据库，全部凭证撤销成功后才标记完成。失败保持冻结和必要引用，可原身份重试；若凭证已清理而墓碑写入失败，则由维护任务继续完成。
- 外部连接能够读取任意历史、摘要及作品，统一要求本人分别同意外部访问和敏感信息处理；关键词未命中、sensitiveHistory=false 或已检查缓存都不作为放行依据。令牌签发、REST 读写、MCP HTTP 入口及工具自身共用检查，缺少任一授权即拒绝；本人 Cookie/小程序查阅与数据权利入口保留。授权页和政策明确告知这一要求，政策内容变化自动更新版本并要求重新确认。
- Payload写钩子阻止撤回/到期/删除后的迟到写入。删除不会被新同意重新激活。隐私权利请求通过政策中的联系渠道处理；在线受理尚未开放。
- 导出保留用户输入/图片归属，回应带AI标签；图片内容缺失时注明状态并继续导出其余数据；不导出凭证摘要、恢复码摘要或OSS内部对象地址。原生退出/删除清理登记过的临时下载文件；设备系统备份及自行导出的副本另行处理。

## 生成标识

- 聊天身份提示、每轮回应与五类作品周边显示“AI生成”；外部结果提示来源声明。
- 复制回应及H5对生成区域的选择复制附带标识；小程序卡片/表格长按复制带标识。复制恢复码、连接配置与用户原文不冒称AI生成。
- PNG保留原640×400绘图区，新增48像素底栏。32像素字体、黑白高反差位于边缘，文字高度覆盖最短边5%的要求。AIGC放入唯一UTF-8 iTXt字段，CRC正确，可独立读取。
- HTML正文与head的AIGC元数据一致，继续转义内容并保留禁止脚本/外连的CSP。
- 附录E七个字符串字段齐全。使用真实公司名称，不编造平台编码或备案号。内容编号用稳定摘要生成；平台/BYOK标记1，外部声明标记2并注明由平台渲染、来源未独立核验。
- 上传原图不标记为平台生成；识别到已有PNG文本块或JPEG/WebP XMP中的标准AIGC后，在压缩JPEG中只保留该来源标识，不保留GPS/其他EXIF。已识别但损坏或冲突的标识拒绝上传，不暗中剥除。未声称识别任意私有格式或隐形水印。

原共享工作目录曾完成含并行后台的隔离联验，不能将那个结果当作本 PR 分支已通过。新版分支的验证结果记录在 PR，微信真机、真实对象存储/备份以及线上作业仍需单独验收。

维护入口默认只预览：显式指定 `HELLO_DATABASE_URI` 与服务端密钥后运行 `tsx scripts/privacy-maintenance.ts`；确认相同目标再加`--apply`。恢复时保持停流量，配置外置清单，先`--restore`预览，再`--restore --apply`清理并核验，最后才恢复流量。不得用旧数据库备份覆盖删除清单；本次没有对真实备份、真实OSS或真实用户执行维护。

维护中的单个身份清理失败不阻断其他身份；完成独立身份和过期凭证的清理尝试后，汇总失败并以非零状态退出，不能当作恢复完成。结果包含成功/候选数量，失败项仅记录与删除清单一致的身份摘要，不输出原始身份、对象路径或底层错误正文。全局凭证清理的部分失败同样汇总；修复问题后重试，保持停流量直至全部成功。回归使用故障替身验证第一个身份失败后仍清理后续撤回/到期身份、多个失败汇总、凭证部分错误和成功重试，不替代真实 OSS/运营后台验收。

恢复时也逐个重放没有数据库归属记录的删除摘要，直接清理该摘要对应的对象前缀，覆盖数据库与对象快照时间不一致或上传未提交记录的情况。预览计入这些身份但不访问对象存储；执行时去重、失败汇总、可幂等重试。须选择与恢复对象一致的存储配置；数据库存储模式不访问 OSS，不能用来验证已恢复的 OSS 快照。回归使用合成对象集合验证孤立图片删除、他人图片保留和故障重试。

尚需公司执行：旧无授权身份的留存盘点/到期处置、日志/物理介质回收、第三方副本处理、备份恢复演练和墓碑最终清理；当前实现诚实保留这些边界。年龄识别、监护人同意、危机干预完整闭环和拟人化专门申请仍属其他整改项。

2026-10-13 复审修复：图片接收方告知只限制图片入口，不阻止普通文字授权或使用；实际敏感输入/历史触发单独授权后才设置敏感历史标记。PNG 先扫描全部文本块，重复 AIGC 在任何解压前拒绝；全部文本共享 64 KiB 编码/解码预算，单个来源标识最多 16 KiB。该预检早于图片解码器读取元数据。新增测试使用合成图片、模拟审核结论和模拟存储，不能代表实际审核服务或数据库联验完成。

后续复审补充：外部插画 PNG 底栏直接显示“AI 生成（外部客户端声明）”，元数据同时保留来源属性。有效且未过期的相同授权提交不追加记录、不延长到期时间；授权变化与恢复码轮换仍记录，但每个身份的历史最多 64 条 / 128 KiB，并固定保留最近一次同意及其政策快照。此界限不是无限期运营审计的替代。清单绝对路径校验不证明磁盘持久性，实际挂载、权限及独立备份仍须由运营验收。

导出资源限制：按身份归属逐条读取（包含凭证摘要清理和图片缺失说明），总 JSON 最多 8 MiB、1000 条；图片在 base64 扩容前计入剩余预算，超限返回 413，不生成部分文件。当前单进程最多并发 2 次，同一可信来源最多占 1 个并发位；全局每分钟 20 次、每身份每分钟 2 次、每可信来源每分钟 4 次；所有失败路径释放并发位。先检查并发，再同时检查身份与全局额度，全部通过后统一扣减；拒绝的重试不消耗任何一级额度。多实例前须把该限制迁到共享设施。大量数据的完整副本走政策联系渠道，不承诺超限请求已经完成。
删除完成时清空敏感历史标记与到期时间，仅保留冻结墓碑。清单先同步文件，再逐级同步父目录至根目录；同步失败不进入后续数据删除。故障顺序为模拟文件句柄测试，另有独立临时目录真实读写；不代替生产存储的断电验收。

授权并发保护：资料增加递增 revision，通过配置的 SQLite 适配器用一条带身份、版本和状态条件的 UPDATE 完成比较及写入，冲突返回 409 并提示刷新后重新确认。授权、撤回、恢复码、敏感历史与删除墓碑更新共用这一保护；迟到的请求不能重新激活已撤回或冻结的资料。独立 SQLite 测试验证增量迁移保留旧记录、延迟授权与撤回竞争、同版本双写及删除冻结；这不是 #383 运营后台的完整联验。

网页复制仅在选区完全位于同一个 AI 来源容器、且所有选中文字都明确标为生成内容时加标签。图片加载/失败、表单系统说明、用户填写及混合选区保留浏览器原始复制；纯生成的跨单元格选择和图片说明仍附带来源。回复失败/未完成提示也标为系统文本。真实 Chromium Range/ClipboardEvent 在合成 DOM 上验证 19 种单来源、片段、跨消息和系统/生成混合场景；真实 React 图片组件另验证加载、失败与说明的来源属性。这不是完整线上页面验收。

恢复入口限流：每个代理确认的来源每分钟最多 20 次（包括失败与畸形请求）；格式和入口模式正确后，数据库恢复查找另受每分钟 200 次的全局上限保护。单来源被拒重试不扣全局额度。部署须使用覆盖 X-Real-IP 的可信代理、保持应用端口只监听回环，并显式设置 HELLO_TRUST_PROXY=true；仓库预览 Compose 已配置，对应 Nginx 模板覆盖该头。缺少可信来源时部署模式拒绝恢复；不使用客户端可追加的 X-Forwarded-For。未启用代理的本地开发共享本地限额；多实例仍需共享限流。5 项入口回归覆盖畸形/无效码、跨来源隔离、伪造转发链、配置缺失及全局窗口。未部署这些配置。

敏感历史检查先看当前输入和已有敏感标记；仅未检查的旧历史按身份/id 游标每批最多 32 条读取 id/input，遇到敏感内容即停止，不读取回复或作品字段、不累积全部记录。分页不计算全量总数，1000 条普通历史仅需 32 次查询。检查结果连同 historyInspected 状态使用授权版本保护保存，普通旧历史也只扫描一次；每次新输入仍重新判断，撤回敏感授权后不得使用敏感输入。增量迁移将既有资料标为尚未检查，删除完成清空检查标记。

同一恢复码从首次查找、旧凭证撤销到新凭证签发使用互斥保护，重叠请求返回 409，失败后释放保护以便本人重试；不排队执行第二次撤销来作废刚签发的凭证。当前单应用进程与上述限流边界一致，扩容多进程前必须更换共享租约。回归覆盖查找和签发两个暂停点，确认只返回一个有效成功结果，失败后仍可重试。

凭证并发补充：同一身份的恢复、签发、撤销和删除共用可重入的进程内互斥保护；恢复在持有保护后重新核对资料状态和恢复码，删除中或已删除的身份不能恢复、不能签发连接。`/token` 在保护内重新鉴权，不能沿用恢复前查到的旧 bearer。批量撤销或数据删除返回部分错误也按失败处理，不写入完成墓碑。已删除墓碑不退回 deleting，重放会清除残留并保留首次删除时间。恢复扫描使用 id 游标、每批最多 100 条，只投影 owner/id 及必要状态，不加载聊天正文、图片或 ADK JSON。独立 SQLite 回归包含真实凭证写入/撤销、暂停点并发、失败重试和墓碑重放；对象删除仍使用替身，运营后台不在本分支范围内。身份互斥仅覆盖当前单应用进程；执行独立维护 CLI 前须停流量，避免另一进程并行签发凭证。多进程扩容前需共同使用数据库租约或凭证版本机制。

再次复审：HTTP 隐私写操作在读完请求正文后，持有身份互斥保护重新鉴权，覆盖授权、撤回、恢复码轮换、删除和退出；旧 Cookie/小程序凭证不能在恢复后修改资料或撤销新凭证。接收方变更先清理旧 bearer，再写新授权，任何批量撤销失败均保留原授权与历史，重试完成后旧连接失效。自助导出只读取对话与摘要等本人记录，不读取内部 ADK 快照，避免带出管理员知识原文及临时引用地址；政策与导出说明同步标明边界。图片删除先每页最多 100 条投影 id/object 验证全部引用，再清理身份前缀对象，最后分批投影删除数据库记录；不读取 base64，不累积全身份图片，任一对象或批量记录清理失败均可重试。

外部历史补充回归使用独立 SQLite 授权/凭证与真实 REST/MCP 入口，覆盖英文健康及受虐描述、地址和电话，在未扫描及已缓存两种状态下均于读取前拒绝；开启敏感授权后新连接可继续。会话标题、历史、请求结果、摘要、作品下载、外部生成/整理及令牌签发均受同一门槛限制，MCP 工具也单独验证。本人 Cookie/小程序查阅仍可使用。返回的业务历史/摘要使用替身，此验证不替代 #383 的真实运营联验。

业务请求撤权时序：REST 与 MCP 读完正文后重新鉴权，再在同一身份的执行保护内检查授权并处理；恢复、接收方变更和删除不能跨过已准入的业务执行。业务请求可并发；首个凭证变更先登记写入意图，阻止新业务进入，等待已准入工作结束后自动执行，重叠的第二个变更返回 409。已准入请求只能在其许可仍有效时延长后台流式工作，已结束请求的异步回调不能重新准入；AG-UI 保护持续到后台生成结束，包含断线及失败，MCP 保护持续到工具响应完成。独立 SQLite 测试覆盖慢正文跨恢复/接收方变更后拒绝旧凭证、真实 MCP JSON 传输和流式结束释放；业务生成和图片仍使用替身。此保护仍仅适用于单应用进程，维护 CLI 和多实例限制不变。聊天展开的联想依据统一为完整文本，微信长按复制包含 AI 标识及外部来源声明。

撤权防饥饿与权限补充：本人 Cookie/小程序的隐私写操作和连接管理使用独立控制额度；外部 bearer 在扣额度前被拒绝进入隐私管理，不能用业务流量或越权重试耗尽本人额度。真实 REST/MCP 业务额度耗尽后，本人仍可撤回、退出、变更授权、轮换恢复码、撤销连接或进入删除确认。外部 REST 原始图片及媒体作品下载必须有敏感授权，即使图片从未出现在输入历史也不能绕过；本人仍可查阅已有图片。并发历史检查的 CAS 冲突会重新读取，只有授权/状态/期限未变时幂等合并检查标记；撤回、删除和授权变化仍拒绝旧请求。独立 SQLite 与真实 HTTP/MCP 传输回归覆盖这些边界，图片正文/业务生成仍为合成替身，删除这里只验证确认入口和额度隔离，真实完整删除由本分支 privacy-check.ts 独立库检查覆盖。

执行等待与大清单边界：凭证变更最多等待现有工作 80 秒（早于客户端 90 秒请求截止），超时返回 503，明确本次变更未执行，并清除等待者和计时器；旧变更不会在稍后执行。不会通过过期一个仍在真实读写的许可来伪报撤权或删除成功，底层工作恢复后可重新提交变更；持续的数据库/存储故障仍需要修复。恢复清单改为 64 KiB 块流式解析 NDJSON，单行最多 4 KiB，重复摘要在集合中去重，不保留原始文件、行数组、时间或记录对象。完整清单验证完后才开始扫描/删除；恢复仍需为不同身份摘要及待清理身份集合提供内存，不能将其视为磁盘索引方案。合成大文件覆盖 50001 条重复记录、跨块/CRLF/末尾无换行及损坏/超长行；未操作真实备份。

匿名导出来源隔离：导出和恢复共用可信代理来源提取，使用被代理覆盖的 X-Real-IP，忽略 X-Forwarded-For。生产缺少代理保护或有效地址时拒绝导出；本地开发共享一个本地来源额度。更换 Cookie/匿名身份不能绕过同来源额度或占满两个并发位，被拒请求不消耗其他来源的全局额度。此约束不替代网关对分布式流量的防护，多实例仍需共享限流。微信图片作品的说明文字带 AI 标识，外部作品同时保留客户端声明；加载提示仍是系统状态文案。
