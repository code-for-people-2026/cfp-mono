# 万相文生图接入

DeepSeek → `generate_image` → 百炼万相 → 文件验证与图片审核 → 私有 OSS → `save_greeting` 图片作品 → 本人鉴权展示、下载。

## 行为

- 模型 `wan2.6-t2i`，北京地域，一轮一张，方图 1280×1280、竖图 1104×1472、横图 1472×1104。只发送必要画面描述，不自动发送完整历史或上传原图。不支持原图编辑。
- 保留供应商水印和有效来源元数据，追加可见“AI 生成”；去除 EXIF，转 JPEG，最长边 2048，现有 2 MiB 存储上限。
- 图片存入当前部署的 `HELLO_MEDIA_STORAGE`。ECS 已配置 OSS；本地测试可用数据库。客户端沿用 `/api/hello/media/:id`、`/api/hello/artifact-image/:turnId/:artifactId`，需本人凭证。链接不是公共分享地址。
- 先保存 `submitting`，收到回执后保存 `pending` 和任务编号，下载/审核/保存完成后记 `stored`。网络、存储或审核服务暂不可用时，可在对话中“继续取图”，复用编号并重新审核；已完成轮次幂等返回。未知提交回执禁止自动重提，供应商任务过期、审核拒绝或风险待人工判断时不能恢复。
- 原服务端会话锁覆盖执行，避免同会话并行提交。正常执行上限 180 秒，SSE 每 15 秒保活，客户端等待上限 240 秒。没有后台任务队列，服务进程中断后须重新打开记录继续取图。
- 生成图片纳入隔离、数据导出与删除。配置供应商后隐私政策版本会变化，须按现有流程重新同意。
- BYOK 只改变对话模型的付费方，文生图仍使用平台百炼密钥。所有模式在首次提交前统一预留每身份和全站的生图任务额度，同一身份的不同会话共享额度；不依赖平台文字模型额度。描述审核拒绝不会预留，额度不足返回 429 且不会调用供应商或留下“提交结果未知”状态。已经取得的额度不因回执丢失、下载失败、图片审核拒绝或保存失败退还。
- `pending` 继续取图、`stored` 图片复用不再预留生图任务额度或提交；即使跨 UTC 日、生图额度耗尽或新生成被暂停，也可恢复原任务。`pending` 每次重新审核仍须有独立图片审核额度，耗尽时保留 `pending`，恢复额度后继续取图；`stored` 直接读取不再调用审核。`submitting` 仍禁止重提。

## 部署配置

1. 为北京百炼配置专用 `DASHSCOPE_API_KEY`。可用 `HELLO_IMAGE_WORKSPACE_ID` 选择新业务空间专属域名；留空使用默认北京接口。限定密钥仅访问 `wan2.6-t2i`，不使用 OSS AccessKey 代替百炼密钥。DeepSeek 的 BYOK 仅用于对话，图片由平台百炼账户承担费用。
2. 图片审核二选一：现有 HTTPS 代理及其接收方告知；或 `HELLO_IMAGE_REVIEW_MODE=aliyun-green`，配置独立的 `HELLO_GREEN_ACCESS_KEY_ID`、`HELLO_GREEN_ACCESS_KEY_SECRET`。后者使用上海内容安全增强版 `baselineCheck`，RAM 运行权限是 `yundun-greenweb:DescribeUploadToken`、`yundun-greenweb:ImageModeration`（Resource 为 `*`）。注意 SDK / CLI 产品名是 Green，RAM 权限前缀是 `yundun-greenweb`，不能写成 `green:`。只上传到服务返回的临时桶，不需要将本应用 OSS 公开或授予其全桶访问。`none` 放行，`high` 拒绝，`low` / `medium` 待复核，异常不放行。
3. 复用现有私有 OSS 配置。备份 SQLite 后通过正式部署启动迁移（不要对现有部署库运行本地 db:init），新增 `greetings.image_generation`、`media.generation`、`media.generation_key` 及唯一索引，不修改旧图片。
4. 配置好云服务后，在隔离预览实例实测一张无敏感信息的图片、鉴权下载、刷新/恢复、OSS 对象以及删除。验证通过再发布。配置值不得写入代码、提交、命令日志或 Issue。

| 配置 | 默认每日上限 | 作用 |
| --- | --- | --- |
| `HELLO_IMAGE_OWNER_DAILY_LIMIT` | 10 | 同一身份新提交的图片生成任务，跨模式和会话合计 |
| `HELLO_IMAGE_GLOBAL_DAILY_LIMIT` | 100 | 全站新提交的图片生成任务 |
| `HELLO_IMAGE_REVIEW_OWNER_DAILY_LIMIT` | 100 | 同一身份的图片审核尝试，上传、旧图片补审、生成图重审及结构化插画共用 |
| `HELLO_IMAGE_REVIEW_GLOBAL_DAILY_LIMIT` | 1000 | 全站图片审核尝试 |

生图任务额度按 UTC 日期重置，配置须为非负整数，0 暂停相应新生成。两项计数在当前 Payload 文件 SQLite 的同一写事务里预留，任一额度不足会整体回滚且不会创建新的身份计数键；跨进程和重启仍有效。计数仅存身份哈希，使用独立 `image:` 命名空间，旧日计数在后续成功预留时清理，不改写文字模型或投诉入口额度。复用独立原生连接及 5 秒占锁重试；数据库不可用、内存或远程等不支持的数据库配置会拒绝提交。

图片审核预算使用同一原子机制及独立 `image-review:` 命名空间，与生图、文字模型和投诉入口计数分别清理。每次调用审核器前预留，失败或回执不明不退款；审核额度设为 0 会暂停新的审核尝试。额度不足返回 429，供应商不会收到请求，也不会据此创建违规案件、证据或审核结论；图片不会绕过审核发布。

小型 ECS 使用 `Dockerfile.preview` 时，将 `typecheck` 与 Next webpack 构建分成独立步骤，避免两个编译进程同时占用内存。`HELLO_BUILD_TYPES_VERIFIED=true` 仅在前一步类型检查成功后设置；普通构建仍执行 Next 内置类型检查。不要以这个构建参数跳过独立检查。长期叠加的预览镜像若达到 Docker 层数上限，可导出已编译镜像的文件系统并重新导入为独立镜像，再恢复运行用户、工作目录和启动命令；保留旧服务及其镜像以便核对。

## 验证入口

`NODE_ENV=development HELLO_IMAGE_LIVE_TEST=true pnpm --filter @cfp/hello-agent test:images:live` 是显式付费验收，须先构建 H5 和 Next 并提供真实模型、图审、OSS 与隐私运营环境。测试父进程需要开发模式以初始化全新隔离库；脚本启动的 Next 子进程仍使用生产模式。生产镜像内执行时同样显式设置父进程环境，否则空库不会建表，尚未调用供应商就会失败。它只在新建临时数据库中创建合成身份，不修改部署库或核验真实年龄；通过原生凭证发送实际 AG-UI 请求，检查真实媒体作品、Green 放行、OSS 哈希回读、本人/他人/匿名读取、导出及对象删除。失败时也清理测试身份前缀；清理失败保留隔离库供重试，不把供应商模拟结果当作实测。
