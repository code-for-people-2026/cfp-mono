# 好人阿 J / a jOKer：验收与微信测试指南

本项目同时提供 Taro H5 和原生微信小程序，统一调用同一个服务端。H5 能运行、小程序能编译，并不代表微信真机已经验收通过。

## 一、先看懂 CMS

入口：<http://127.0.0.1:3310/admin>。每个列表的标题下都有用途说明。已有账号可能保存过旧列偏好，可以点击「使用推荐列」更新当前账号在该列表的列与排序，不会修改业务数据。

| 分组 / 资源                 | 每行代表什么                     | 默认重点                                         |
| --------------------------- | -------------------------------- | ------------------------------------------------ |
| 业务验收 / 祝福会话         | 一段用户聊天的容器               | 会话标题、创建时间、更新时间                     |
| 业务验收 / 生成轮次与吉祥话 | 一次输入和对应生成结果，包括失败 | 灵感输入、吉祥话、状态、使用方式、模型、创建时间 |
| 业务验收 / 灵感图片         | 用户发送的图片素材，不是生成图   | 缩略图与格式、图片 ID、创建时间                  |
| 运行诊断 / ADK 会话         | 平台或 BYOK 单轮执行的内部轨迹   | 执行事件数、调用工具、记录 ID、更新时间          |
| 运行诊断 / 会话执行锁       | 防止并发执行的临时锁             | 会话标识、到期时间；正常完成后通常为空           |
| 系统管理 / 管理员           | 后台管理账号，不是聊天访客       | 邮箱、创建时间、更新时间                         |

输入与回复最多展示三行，点击进入详情看全文。输入中的图片编号可与「灵感图片」对照。ID、所属访客、提示词版本、联想依据等仍保留在详情或可选列里，没有删除数据。

## 二、H5 验收

入口：<http://127.0.0.1:3310/chat/index.html#/pages/chat/index>。

- 界面只有聊天应用本身：大屏居中、最大 420px 宽，小屏占满宽度；没有宣传页、假手机、假时间或微信胶囊。
- 顶部显示「好人阿 J / a jOKer」，欢迎语自称「阿J」。自动续接最近记录，不展示会话列表、新建入口或编号；底部输入、选图、助手选择仍可操作，后台入口在「设置」中。
- 平台助手：发送一句文字，看到生成中、真实回复及保存提示；在 CMS 中找到匹配的输入、回复和「平台助手」来源。
- BYOK：切换模式并使用自己的 DeepSeek 密钥；确认产物来源为 BYOK。当前只支持 DeepSeek，不宣称已接入所有供应商；不要把密钥粘到聊天正文或提交到 Git。
- 自带 Agent：按界面授权 MCP 客户端，由外部 Agent 生成并保存；在 CMS 中看到「自带 Agent」，不应因此增加平台 ADK 轨迹。接入方式见项目 README。
- 图片：验证选择、删除、预览和发送，再在 CMS 对照图片与输入。必须包含正常手机照片，不能只测高度压缩的纯色缩略图；原图最多 5 MB，处理后最多 2 MB。ECS 的图片文件存私有 OSS，CMS 只保留所属访客和对象引用；检查本人预览正常、其他访客读不到、后台缩略图正常。未配置 OSS 的本地演示仍兼容 base64。模型的图片理解质量需要独立验收，成功保存不等于理解准确。
- 刷新后最近记录中的原有输入与产物可恢复。当前是访客设备身份，不是 `wx.login` 账号；H5 与微信端身份不会自动合并。先前其他记录仍保留在 CMS，不会被删除或混合。

阿J当前提示词版本为 `aj-v2.1`；检查新回复而不是拿旧版本已保存的内容验收新性格。名称与人设调整不改权限、数据库结构、现有管理员或历史数据。

### 记忆血条与广告压缩

- 顶部「阿J的记忆」表示本产品 18,000 估算 token 预算的剩余比例，不是模型窗口、准确计费量或聊天档案容量。至少三轮完成的对话后，才有可以压缩的较早内容。
- 点击血条，检查剩余空间、摘要可能遗漏细节的说明，以及广告类型。没有广告位时，本地明确显示「开发演示 · 非真实商业广告」，不可作为真实广告接入验收。
- 本地演示等待五秒才能完成。提前关闭后，记忆和原记录不变；重新观看后点击「看完了，整理记忆」，才会调用真实模型生成摘要。
- 成功后可用空间增加；最近两轮保留原文，旧轮次转为摘要供下次生成使用，CMS 内完整聊天仍在。可以在较早轮次放入一个无敏感信息的测试代号，压缩后询问它，人工检查是否记住。
- 压缩失败保留原上下文和本次观看资格；有效期内可以重试，不需重复看广告。网络重复提交不能触发第二次压缩。BYOK 使用本次输入的密钥，重试前可能需要重新填写。
- 血条耗尽时发送受阻，提示先整理记忆；服务端也执行相同限制，不能只改前端绕过。此分支由隔离测试库覆盖，无需为了验收塞满用户真实聊天。
- 刷新后血条、摘要和完整聊天应恢复。CMS「祝福会话」详情的「对话记忆与压缩凭据」保存相关状态；摘要提示词 `memory-v1` 与阿J人设独立维护。

真实微信激励视频尚待提供广告位并在真机验证。当前客户端适配只接受完整观看回调；尚无服务端观看证明验证，因此非本地环境默认禁用，不能作为可上线的广告计费方案。没有执行真实广告点击或产生广告收入。

## 三、微信侧的三个测试层级

### 开发者工具模拟器

2026-09-30 用户已将 `/Applications/wechatwebdevtools.app` 覆盖安装为 Intel / x64 版，解决原 ARM64 包的 CPU 类型错误。本机 CLI 已确认版本为 `2.02.2608070`，Codex 连接授权通过，微信登录有效。阿J已在原生小程序模拟器运行，文字发送、真实 DeepSeek 回复与 CMS 保存提示通过检查；这不等于手机真机验收。

1. 从[微信开发者工具官方下载入口](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)安装与 Intel Mac 匹配的版本。
2. 在仓库根目录执行 `pnpm --filter @cfp/hello-agent-miniapp build:weapp`。
3. 导入 `apps/hello-agent-miniapp`，其中 `project.config.json` 的 `miniprogramRoot` 指向 `dist/weapp/`。
4. 使用自己的小程序 AppID，并由有项目开发权限的微信账号登录。2026-10-01 已按用户提供的信息切换为 `wx692320cdac058519`，不再使用此前测试号；拥有 AppID 不代表已完成服务类目或公开发布审核。
5. 检查页面、键盘、图片选择、请求和错误提示。本地关闭域名校验只用于开发，不作为发布方案。

本机调试的具体操作：

- 服务端保持运行在 `http://127.0.0.1:3310`。当前已有服务时无需再开一个；要改后端代码时停掉自己的旧服务，再执行 `pnpm --filter @cfp/hello-agent dev`。
- 另一个终端运行 `pnpm --filter @cfp/hello-agent-miniapp dev:weapp`，保存 Taro 源码后持续重编译 `dist/weapp/`；开发者工具再编译 / 刷新。
- 导入路径是 `/Users/sunmer/Documents/cfp-mono/apps/hello-agent-miniapp`，不是后端目录，也不是 H5 地址。项目不使用微信云开发，Payload / ADK 是独立后端。
- 当前项目 `urlCheck: true`，真实检查域名。要连接 ECS，必须在同一 AppID 后台把 `https://aj-preview.codeforpeople.cn` 加入 request 和 downloadFile 合法域名。本机 localhost 调试若临时改变设置，不得把这个例外当作体验版验收通过。
- 在调试器的 Network 查看 `miniapp-identity`、`config`、`sessions`，发送后查看 `greet`；成功响应应为 2xx。Console 看脚本异常，Storage 只应保存设备身份令牌，不能出现 DeepSeek Key。
- 先发「你叫什么名字」，确认自称阿J；再发「今天面试没过」，检查是否理解失落而非强行祝贺。最后在 CMS 对照输入、输出与 `aj-v2.1`。
- 开发者工具模拟器和后端在同一台电脑，可以使用默认本地地址；手机扫码预览需另行配置可访问的后端。

本机已用开发者工具自带的 `wechatide` Skills / MCP 接口完成自动开窗、编译、页面读取、输入和点击。连接授权与微信扫码登录是两件事：`wechatide auth -c Codex` 请求客户端连接授权；仅登录失效时才需要微信扫码。本轮连续超时且没有弹窗，完整退出本次启动的工具后重新发起授权，成功返回待确认任务，用户允许后授权完成。该现象与[腾讯工程说明中的单实例授权问题](https://github.com/TencentCloudBase/CloudBase-AI-Toolkit/blob/main/plugins/experts/miniprogram-clouddev-expert/agents/miniprogram-clouddev-expert.md)一致；不能将连接超时直接判断为用户拒绝授权，也不能绕过确认。

### 手机扫码预览

在开发者工具中点击「预览」，使用有相应权限的微信扫码。二维码用于手机运行小程序，不是 H5 网址，也不等于公开发布。[腾讯官方预览说明](https://cloud.tencent.com/document/product/647/32399)

手机不能通过 `127.0.0.1:3310` 访问电脑。本项目的稳定真机测试方案需要先单独部署可访问的 HTTPS 后端，再编译客户端：

```sh
HELLO_API_ORIGIN=https://你的后端域名 pnpm --filter @cfp/hello-agent-miniapp build:weapp
```

后端域名是公开配置，不是模型密钥。平台密钥、数据库、Payload 和 ADK 均留在服务端；在微信管理后台配置实际使用的请求 / 下载合法域名。只上传小程序前端不会同时部署后端。

### 给指定人员的体验版

准备有效 AppID、开发权限和可访问后端后，常规路径是：开发者工具「上传」→ 微信公众平台「版本管理」找到开发版本并设为体验版 → 在成员管理中添加体验成员 → 向这些成员提供体验二维码。后台菜单以账号实际界面为准。

体验版面向指定测试人员；面向公众的正式版另需提交审核并发布，相关主体、服务类目及 AI 功能要求需按届时平台规则检查。2026-10-01 用户已授权上传测试版本，但未授权提交审核或正式发布；上传结果、体验版设置和真机可用性应分别记录，不可混称。
