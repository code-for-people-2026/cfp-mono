## 用户路径

首次打开只显示简短登录小窗：一句提示、昵称和头像、微信登录按钮和“登录与使用说明”小链接；未登录不能关闭进入业务。昵称默认先随机生成，可重新生成或通过带下划线的链接使用微信 `type=nickname`；头像使用 `chooseAvatar`。主动清空后，服务端为新账号生成默认资料，已有账号保留原资料。点击“同意并微信登录”后进行微信平台隐私交互和 `wx.login`。旧记录保留是说明内的可选项，默认不选。登录完成后，单独显示生日小窗（日期选择、继续按钮、“为什么需要生日？”链接）；已有有效申报时不重复询问。

生日只在页面内计算申报年龄段，不上传、不存储、不发给模型；按北京时间的日期判断14岁和18岁边界。提交后清除完整生日。未满14岁只提交年龄段并进入监护人支持提示；其他年龄段在本人填写姓名、证件并单独勾选同意后提交申报和核验。核验申请和信息提交合为一次按钮操作，仍保留服务端单次请求和权限检查。长告知、隐私及帮助入口放在说明链接里；生日申报不会获得成年权限。年龄结论与使用授权均有效时恢复聊天，不重复填表。

普通微信登录只取得账号身份。腾讯云 `MinorsVerification Type="1"` 核验所填姓名证件的年龄，不证明操作者本人；不用手机号健康守护模型推定，不收证件照片。仅将 `Result="0"` 且 `AgeRange="[18,+)"` 视为成年；未成年区间不转换成供应商未提供的14岁分界。已申报未满14岁先提供明确的对话限制和监护人支持提示。本人确认已满14岁且生日误填时，可以进入单独的身份证更正流程。

成年、未成年、未知、失败、服务不可用、取消、过期和需复核分别显示。未成年人适配与监护人流程尚未完成，因此未成年/未知/需复核期间暂停新生成、上传、广告/记忆整理和外部连接；继续保留本人历史、隐私政策、导出删除和同一运营反馈入口。这是当前功能分流，不宣称产品永久仅向成年人提供服务或完整未成年人保护已完成。

## 服务边界与身份安全

- `POST /api/hello/wechat-login` 仅原生小程序；服务器向固定微信官方地址交换一次性 code。客户端不能传 OpenID、owner 或年龄结论。只存 AppID 范围的 OpenID 摘要、业务身份及登录同意版本/时间；不用 `session_key` / `unionid`。
- 仅凭有效旧小程序凭证＋显式保留选择首次绑定匿名历史。微信已有绑定时恢复原账号，不自动合并当前其他历史；同一个旧身份不能被两个微信账号并发绑定。绑定后撤销旧匿名凭证。
- 旧匿名、网页访客、恢复码凭证都不获得微信权限。微信认证字段来自服务端签发凭证；外部令牌只能由有效微信身份和年龄状态下签发，并继承身份绑定。H5 不能凭访客 Cookie 绕过年龄限制。
- `GET /api/hello/age` 查询业务端状态；`POST age/challenge` 保存年龄申报和单独同意并生成5分钟单次请求；`POST age/submit` 绑定当前微信身份并在供应商调用前消费请求；`POST age/cancel` 不清除既有未成年/成年/需复核证据。
- 数据库唯一锁串行处理登录与核验，租约60秒、供应商超时12秒；返回后再次核对租约和隐私删除/撤回状态。进程中断或结果不明不会成为成年；客户端可查询自身持久化结果，新尝试须重新发起。每身份每日最多5次供应商尝试；另有现有单进程请求限流。上线多实例需配合共享边缘限流控制登录滥用。
- 所有用户 REST 写入口（保留隐私/反馈/撤销令牌例外）、外部 REST 读取、MCP入口及每个读取图片/工具调用检查年龄。数据库业务写钩子也阻止已经失效或追加复核后的迟到写入。内部运营合成评测不使用用户凭证，不伪造用户年龄；其年龄状态为空，不能通过用户 API 使用。
- 第三方接口是同步查询，没有公开异步回调或凭 RequestId 重查结果接口；没有开放客户端能伪造成年的“回调”。`AgeService.requireAdditionalVerification()` 仅供未来可信风险/监护服务接入，本版无客户端清除此状态的接口。申诉使用帮助页的公开联系渠道，本版没有在线案件受理；后续解除须新的可信核验证据与审计。

## 最小保存与删除

姓名/证件只在客户端当前表单和服务端请求内存存在，提交完成后清空表单；不写 storage、数据库、应用日志、模型或运营证据。供应商返回原始描述/异常不回显，只存结果、来源、随机请求凭证、同意版本/时间、核验时间及业务有效期。30天有效期是本产品策略，不是腾讯官方承诺。年龄段只保存用户申报，`assurance=identity_details_match` 标识真实核验强度；under14申报本身没有此强度。

年龄告知纳入现有隐私政策版本，供应商处理说明变更后要求重新核验/同意。导出包含最小年龄状态；在线删除同时删除年龄状态、微信绑定和凭证。进行中的核验须结束或超时后重试删除，迟到响应不能复活已删除数据。备份、代理/APM的正文与URL采集、供应商侧留存仍须依既有隐私规程确认；尤其不要记录提交正文或微信交换请求的 secret/code 查询参数。

## 最少外部配置（在受控服务端配置，不发送到聊天）

1. 真实小程序 `HELLO_WECHAT_APP_ID`、`HELLO_WECHAT_APP_SECRET`；与构建 AppID 一致。微信后台隐私保护指引声明实际处理类型，添加已备案 HTTPS request 合法域名，确认当前基础库支持 `requirePrivacyAuthorize`。需要真机验证授权取消、成功与重新打开。
2. `HELLO_AGE_PROVIDER=aliyun` 使用阿里云信息核验 `Id2MetaVerify`；开通信息核验商品，并授予调用权限。`HELLO_AGE_SECRET_ID`、`HELLO_AGE_SECRET_KEY` 为对应阿里云 AK，临时凭证可设 `HELLO_AGE_SESSION_TOKEN`。固定上海官方端点、HTTPS POST 请求体传参、RPC 签名、版本2019-03-07。也保留 `tencent` 兼容原有供应商，不能混用两家凭证。
3. 核实受托协议、处理地域、留存、权利渠道与必要评估后，将真实完整说明写入 `HELLO_AGE_PROVIDER_DISCLOSURE`，再设 `HELLO_AGE_PROVIDER_APPROVED=true`。缺任何一项均显示不可用并停止供应商调用。此标记只确认配置，不代替权限或年龄结果。既有 `HELLO_PRIVACY_*` 上线配置同样需要完成。

没有生产mock、开发成年开关或借用真实身份的测试路径。`scripts/synthetic-age.ts` 仅在隔离回归脚本中显式注入合成状态；运行时不导入。部署前确认反向代理/APM不采集敏感请求正文/查询参数，配置日志清理和现有隐私维护任务。


## 生日更正与阿里云接入（2026-10-14）

侧栏覆盖整个屏幕，头像昵称和关闭按钮位于胶囊下方；不再重复展示 Agent 品牌标题。未成年提示直接说明“暂时无法开始对话”。

仅生日申报且没有真实身份匹配证据、没有风险复核标记的账号，可以提交 `correction=true`、`declaration=unknown` 申请更正。服务端保存单次请求用途 `challengePurpose=correction`，原申报及限制保持不变。更正表单要求本人已满14岁并单独同意姓名证件处理；成功核验后才更新年龄段。取消、失败、未知或超时都不会放行；已核验未成年及可信服务端的复核标记仍须申诉，客户端不能清除。新增数据库字段采用幂等增量迁移，不修改既有年龄数据。

阿里云二要素接口本身仅确认姓名与身份证是否匹配。仅在 `Code="200"`、合法 `RequestId`、`BizCode="1"` 且证件校验位和日期有效时，根据该已核验证件的出生日期、北京时间日期计算14/18岁分段。生日或身份证本地解析不能单独作为成年证据。姓名证件只存在于请求内存；不进 URL、日志、数据库或模型。证件显示未满14岁时不向供应商发出查询，进入复核支持路径。

官方依据：[接口参数与结果](https://help.aliyun.com/zh/id-verification/information-verification/developer-reference/vatsl9lfmbwe74iv)、[RPC 签名](https://www.alibabacloud.com/help/zh/sdk/product-overview/rpc-mechanism)、[独立开通信息核验](https://help.aliyun.com/zh/id-verification/information-verification/bzagds5rl241tuv2)、[计费](https://help.aliyun.com/zh/id-verification/information-verification/product-overview/eo5ytn0ml54ddd8f)。查询当前部署账号的 `DescribeAntAndCloudAuthUserStatus` 返回 `InforverifyEnabled=false`；RAM 授权不等于开通商品。真实调用仍待开通；隔离回归只用合成身份与供应商回包。
