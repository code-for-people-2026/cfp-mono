# 微信支付关闭边界

首期限时免费。`src/membership/payment.ts` 只实现 `DisabledPaymentProvider` 与 `rejectPayment()`：下单、支付/退款通知、查单、退款及关单一律抛出 `AppError(409, "PAYMENT_DISABLED", ..., false)`。不读取商户环境变量、人数或客户端启用标记，不发网络请求、不创建订单/交易集合，也不修改服务权益。不存在可启用的真实支付 provider。HTTP 入口应先调用统一拒绝函数，不解析通知为可信结果；当前不会返回支付成功通知的成功确认。

## 未来接入契约

`PaymentProvider` 是后续实现边界，当前没有其启用实现。价格、时长、收费时间及退款后权益政策须另行明确。商户、应用、宝宝、原订单号、原订单金额和币种来自可信服务端配置及持久订单；客户端返回不能赋予权益。`PaymentOrderExpectation` 中的测试金额只用于隔离测试，并非产品价格。

通知输入保留原始字节与签名头。未来 provider 必须先用可信平台公钥/证书验证原报文，再解密并校验商户、应用、订单、金额/币种匹配，才可产出 `VerifiedPaymentEvidence`。查询应答也需验签；不能把 JSON 的 `signatureVerified: true` 当作证据。这依据微信支付[原始报文验签说明](https://pay.wechatpay.cn/doc/v3/merchant/4013053249)及[请求应答与回调验签规则](https://pay.wechatpay.cn/doc/v3/merchant/4012365342)。

支付通知携带应用、商户、商户订单号、微信交易号及金额；未来实现必须对照原服务端订单校验。已确认通知可能重复，回调也可能丢失，须持久去重并用同一原订单查单补偿。[支付成功回调通知](https://pay.wechatpay.cn/doc/v3/merchant/4012791902)、[支付回调和查单指引](https://pay.wechatpay.cn/doc/v3/partner/4012082568)。

退款通知有独立商户退款号、微信退款号、原交易号和退款金额。它不带应用 ID，应用归属必须从原可信订单关联，不能凭通知自行创建订单。`refund()` 的提交回执不等于退款成功；结果由验签通知或查询确认。[退款结果回调通知](https://pay.wechatpay.cn/doc/v3/merchant/4012791906)。

## 后续状态迁移约束

以下是后续消费者必须实现的契约，当前没有订单状态机或持久订单实现：

| 输入与原状态 | 后续处理 | 权益边界 |
| --- | --- | --- |
| 客户端宣称成功、取消或报错 | 使用原订单查询；不能凭前端结果确认支付或关单 | 不变 |
| 已验证 `NOTPAY` | 保留待确认；不解释为支付失败，不换单重收 | 不变 |
| 首次验证 `SUCCESS` | 原子保存交易确认及去重键；同一订单只能确认一次 | 仅交给另行明确的权益策略 |
| 重复通知 ID，或另一个通知再次确认同一交易/退款 | 返回已有确认，不再次产生业务效果 | 不重复开通或撤销 |
| 旧/矛盾通知，查询与本地状态冲突 | `needs_reconciliation`，查原单，保留已确认状态，不盲目回退 | 不变 |
| 未支付订单拟关闭 | 先查单再关单；若已支付改走另行授权退款；关单失败重新查单 | 不变 |
| 退款提交或 `PROCESSING` / `ABNORMAL` / `CLOSED` | 保留退款进度；`CLOSED` 表示该退款关闭，不表示原支付撤销 | 不变 |
| 已验证退款 `SUCCESS` | 按退款号与原交易去重记录实际退款；部分退款不得当作全额退款 | 仅交给另行明确的退款权益策略 |

未来 `PaymentConfirmationConsumer.confirm()` 必须把通知编号去重、订单/退款业务键去重和状态写入放进同一持久事务，并以版本控制保护并发。交易与退款确认本身不推导服务时长、价格、历史删除或撤权规则；类型中的 `membershipEffect: "none_until_explicit_policy"` 明确这一点。支付关闭时不实例化这个消费者。

## 验证与后续条件

`tests/membership-payment.test.ts` 验证全部关闭操作、伪造通知、重复请求、环境启用标记以及无网络副作用。它不验证真实签名算法、商户凭据、到账、退款或微信客户端支付；本轮未执行这些真实环境验收。

后续启用仍需用户明确收费/退款权益决策、真实商户与应用绑定、安全保存的商户密钥/APIv3 密钥及可信平台公钥/证书、可保留原始报文的 HTTPS 通知入口、持久订单/去重/查询补偿与审计设计，以及真实环境支付和退款验收。人数 500 不是自动收费开关。官方资料核对日期：2026-10-23。
