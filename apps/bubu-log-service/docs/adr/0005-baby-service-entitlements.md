# 服务权益按宝宝共享，免费配置与事实分开保存

#398 在 #397 的运营接缝后接入 `MembershipService`。同一个运行实例、IdentityService 与 Store 注册 `service-memberships` 当前配置和 `service-membership-changes` 不可变更历史；不新建第二个会员库，不复制 Activity、DailyStats、来源或对话。配置、变更和审计在同一事务提交，迁移只新增这两个表。

服务权益不授予宝宝访问权。每个入口先重新验证身份、宝宝和群绑定，再检查相应聊天或采集权益。历史、图片、修订及恢复状态仍可按原授权读取；服务暂停使用可恢复的 423，避免与 403 撤权混淆。未配置值明确保存为 null，不从首次登录推算免费期限，也不在缺少到期策略时自动停服。人工暂停独立于日期策略，恢复和延长均保留其余政策。

运行中的请求在模型调用、工具副作用、旧库投影和采集游标推进前重查。已发出的远程请求无法撤回；恢复沿用原请求号、轮次步骤和确定性记录 ID，保存已经完成的投影检查点，不重新写入已确认事实。后台与业务使用现有单进程事务队列；旧服务并发写入窗口继续遵循 ADR-0002，不声称跨库原子性。

运营角色及宝宝范围每次重查。配置命令必须提供开始编辑时的版本、请求号和理由；旧版本拒绝，相同请求不同输入拒绝。后台通用 CRUD 无权写配置或变更历史，审计只读角色不能修改服务状态。没有支付产品、价格、订单或自动扣费；支付 provider 全部操作明确拒绝，未来接入仍需独立设计与真实验收。
