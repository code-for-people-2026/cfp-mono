# 私人对话保存执行进度，照护事实仍经 MCP

内置聊天的输入、回复与轮次检查点放在同一 Payload 库的独立 `chat-turns` 集合，按照护身份及宝宝隔离。同一宝宝的照护记录和持久待补事项按宝宝授权共享，其他照护者的私人聊天文本不作为会话历史提供。聊天不会把模型摘要用作宝宝事实，也不建立另一套完整性、统计或来源去重规则。

服务端从当前真实会话签发短期 `chat-agent`，通过 MCP SDK 的 Streamable HTTP client 使用录入模块。工具列表从实际 MCP 读取；宝宝、来源与请求号由运输及执行层注入，模型不能声明权限或身份。图片先按宝宝鉴权读取私有字节，再交给明确支持视觉和工具调用的 provider。原始凭证不进入提示词、模型工具参数或客户端。

提交接口先保存输入再后台执行，客户端按原请求号读取结果。模型工具计划先持久化，工具调用和结果逐步检查点保存；重启或丢响应时恢复原操作，不生成另一次记录写入。只有 MCP 回执确认的内容才显示保存状态，日历和趋势重新读取同一业务投影。待补问题及事件版本固定于本次回答；他人已补齐时拒绝旧答案并刷新，不自动升级版本覆盖。

本阶段沿用单进程服务与 SQLite，并需要受配置的图文模型端点。真实微信插件、模型理解质量与旧站同时写入窗口需分别验收；这些限制不通过内存模型、假登录或自动填默认值掩盖。旧服务并发写入的限制仍以 ADR-0002 为准。
