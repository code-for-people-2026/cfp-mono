# ADR 0009：运行监测、停写备份与隔离恢复

状态：已采纳；属于 [#407](https://github.com/code-for-people-2026/cfp-mono/issues/407)，实现不代表已安装生产定时器。

## 决策

全局运行状态只向每次重新认证的 Payload 管理员开放；不授予家庭事实访问。现有运营与审计角色仍只能看到其宝宝范围内的采集摘要。状态输出限定为计数、时间与固定说明，错误不包含路径、凭证、客户消息或家庭标识。磁盘容量、备份时效、证书期限和清理心跳都是运行信号，不能根据记录缺失判断宝宝健康。

单机部署通过宿主机互斥锁安排备份。校验容器角色、同一私有网络、数据及独立删除清单挂载、生产密钥和明确保留期限后，停止服务及原数据层，保持 PostgreSQL 运行。`pg_dump`、SQLite backup 与加密照片形成同一停写窗口的快照。SQLite WAL 先合并进独立副本，不复制运行锁、环境文件、密钥或删除清单。文件清单逐项校验；整体使用独立密钥 AES-GCM 加密，解密和内容复验后才留下备份。结束时恢复原服务并验证两个健康检查。备份失败不覆盖上一份备份；按已确认期限清理过期备份。

恢复工具只把通过校验的快照放入新建隔离目录。它没有替换生产数据或启动服务的能力。数据库和图片仍须通过原流程验证，并从独立保全的最新删除清单执行 `replayAfterRestore`；清单不随旧快照回滚。密钥与最新清单的异地保管、完整恢复演练、外部通知和证书续期均须另外验收，不能从“备份完成”推断这些步骤完成。

## 代价和边界

停写期间存在短暂服务中断，适合 MVP 单实例规模；不能用于多实例、旧站仍可写入或数据库端口外露的部署。宿主机脚本有 Docker 管理权限，配置及脚本目录只允许运维修改。保留期限未确认时示例配置无法运行，定时器不会自动安装。故障在后台呈现和宿主机留下固定错误码；未接入外部渠道时不得声称已发送预警。
