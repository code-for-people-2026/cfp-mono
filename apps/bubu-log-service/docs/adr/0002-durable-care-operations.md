# 照护事实保留旧库，录入通过持久化操作恢复

沿用身份服务的同一个 Payload SQLite 保存候选、来源、修订、待补充、附件和采集进度，Activity/Baby/BabyUser/DailyStat 仍使用原 Payload 字段与关系。MCP 先提交带稳定请求号和确定性 Activity ID 的操作意图，再写旧库并刷新受影响日期；旧库已成功但响应丢失时，通过读回实际内容恢复，不能再次执行无幂等保证的旧应用 POST。图片使用该服务的私有文件目录与同一宝宝授权，旧公开照片只在输出中改为受保护代理。

这不是跨数据库事务。Sidecar 单进程队列与版本号保护新入口的多人修改，远程写前比较、条件选择及写后读回检测已观察到的旧站变化。Payload REST bulk PATCH/DELETE 的 where 先查询后逐项更新，并非数据库原子 CAS；旧站在最后查询与实际写入之间同时编辑的竞争窗口依然存在。生产同时开放两个写入口前，需要停用旧站写入或在原业务数据库部署原子的版本条件写入端点，不能把条件 REST 请求宣传为已经解决此窗口。检测到冲突保留操作意图与修订，由照护者核对后接受旧库最新事实。

聊天与新可视化读取同一事实投影及统计覆盖，旧构建模式保持原行为；不以补零隐藏未知、不把进行中暂估分钟计入完成总量，也不批量重写历史统计。修订与来源保留撤销标记，采集重放不能恢复误记。代价是必须一起备份旧业务库、sidecar SQLite 与私有附件目录，并按原请求恢复未完成操作。
