# ADR 0007：把原 Payload 数据层迁入境内私有服务

状态：实现中，尚未切换真实写入。关联 #407，依赖 ADR 0006。

## 问题

原服务的数据库位于 us-east-1，历史图片存在公开 Blob 引用。小程序侧鉴权不能撤销公开对象，也无法保证家庭删除覆盖原始审计快照。必须保留原照护模型，又把实际存储、访问和删除纳入同一个可运维边界。

## 决策

新增 `apps/bubu-log-core`，提取原 Payload 七个 Collection 及 hook，保留 Payload 3.77.0 和数据库字段/枚举/约束；源为 sunmer-home 提交 `ac86de31b08bdf413e021e60240da2dcd8e63911`。凭证仍由原 NextAuth 的用户名/邮箱 + bcrypt 流程验证，内部短期 JWT 只用于旧账号归属证明。去掉网页、OAuth 注册、公开后台和首管理员创建入口。

本决策仅替换 ADR 0001 中原 Payload 的物理部署和地址。原表仍是照护事实与既有统计的权威存储；身份/授权/来源/修订仍属于 sidecar，不创建第二份照护事实表，不根据迁移重新计算旧统计。

数据服务只监听环回地址，与 sidecar 共享容器网络命名空间，nginx 不代理该端口。请求同时需要核心令牌和原专用 CMS 凭证。字段及 hook 保持原样；CMS 访问改为仅专用服务账号。业务写入默认关闭，所有旧网页/CMS/webhook 写入停止并核对快照后才开启。

家庭导出使用 PostgreSQL repeatable-read 快照。家庭删除在单个事务内锁定相关旧表，先删除 AuditLog 原文/快照，避免原 SET NULL 外键遗留敏感内容，再删除活动、统计、照护关系与宝宝。用户/第三方登录/其他家庭不随家庭删除销毁。独立删除清单继续由 sidecar 持久保存，恢复时重放。

历史 BabyProfile 没有家庭外键。只有有证据的显式归属映射才能参加家庭导出/删除；不能凭昵称匹配。发现的同库 template_records 属于其他上下文，迁移与删除均排除。

## 切换与验证

1. 只读盘点 schema、引用和计数；源快照流式加密，隔离还原，比较全部业务表的行内容摘要及约束。
2. 在专用验证库测试失败回滚、重复删除、其他家庭/用户/无关表不变，以及原 Payload HTTP 登录、读写与统计协议。
3. 原公开照片先复制、解码去元数据、加密和校验，按家庭与来源生成一个私有引用。覆盖当前活动/头像、AuditLog 历史快照以及 sidecar 的事实、修订、待执行操作与聊天回执；保留原请求指纹与版本，避免重试失效或撤销写回公共地址。
4. 私密迁移清单在切换任何引用前完整写入、fsync 并以 hash chain 校验；残缺尾行拒绝继续。重跑先重放已验证清单，补全 core 已提交、sidecar 尚未提交的中断。最终重新盘点不得有未迁移照片；清单包含精确旧地址，只供后续撤销核对，不能公开。
5. 再处理公开对象撤销。复制完成不等于隐私迁移完成。
6. 停止所有写入，做最终快照；新副本验证后才切换地址和开放写入。切换后不能重新放开旧库写入造成双主。
7. 回滚必须先停止新写入，并保全新产生的数据；不得简单恢复旧库而丢失切换后的记录或删除清单。

测试、代码合并、境内部署和正式平台审核是不同的证据，不互相代替。
