# ADR 0010：私人照护图片的检测边界

状态：已采纳；属于 [#407](https://github.com/code-for-people-2026/cfp-mono/issues/407)。接入代码不代表供应商已开通或上线验收完成。

## 决策

生产 runtime 必须安装图片检测门。本人图片处理选择、宝宝监护授权、供应商处理披露和服务器检测配置共同决定新图片能否进入服务。政策版本随披露变化；新增供应商不会静默沿用旧同意。缺少图片供应商披露只关闭图片处理，已具备完整说明的文字功能可继续使用。

新上传先鉴权、校验来源和图片格式，去除 EXIF 等元数据并规范像素。短事务内复查授权和请求幂等性、预留检测次数；事务提交后才调用阿里云上海 Green `baselineCheck`。只向严格校验的供应商临时桶发送规范化像素、格式和随机请求号，不带家庭、照护者或群消息信息。收到明确通过结果后，再用新事务重查当前权限、隐私冻结、权益、来源和请求号，随后加密落盘。第三方网络等待不占用数据库事务或身份队列，所以撤回和删除可以及时进入冻结。第三方已收到的副本仍依其实际约定处理，不能承诺撤回即可追回。

结果为不确定、未通过、错误或超时时均不保存新像素，也不交给 AI。错误返回固定说明，不带供应商标签、响应、存储地址或密钥。尿布和大便照片可能被误判：提示不构成健康判断，可用文字继续记录，并通过原有隐私申诉入口处理。当前没有人工绕过检测按钮，也不承诺申诉能自动恢复照片。上线前要以适当授权的照护图片单独验证误判率和处理流程，不能据通用合成测试宣称适用性已验收。

通过证明只包含规则版本、规范像素摘要及检测时间，随原 `care-attachments` 元数据保存；不另建照片事实库。有效证明支持同一请求修复丢失对象而无需重复调用。没有证明的历史照片仍按家庭权限查看，但模型专用读取、非历史 Agent 和采集 Agent 不能获取像素；重新选择上传后才检测。历史离线迁移不自动把私人照片交给新供应商。

检测费用由持久化限额约束：每 UTC 日家庭最多 100 次，全服务最多 1000 次，失败也消耗一次；最多两个检测任务同时运行，忙碌返回可重试错误。计数复用 `privacy-state`，只有最近一次使用日及数量，跨日覆盖。家庭计数随家庭删除清除，全局计数没有家庭或个人标识。已通过证明随附件删除；拒绝图片不落盘，申诉沿用现有的请求保留和授权规则。

## 验收与边界

检测有 20 秒总期限；SDK 单次连接/读、OSS 上传也设有超时且不自动重试。已在途的网络操作可能继续至自身超时，但超时后不会开始后续步骤或保存证明。后台只报告本地是否配置，不能把配置存在等同于开通、额度和实测成功。没有放行模式、开发环境自动通过或客户端指定检测证明的接口；合成 reviewer 只能从测试依赖注入。

阿里云资料把 `baselineCheck` 推荐用于公开互联网图片，并说明供应商临时 OSS 定期清理；这些说明不能证明私人儿童图片的适用性、精确留存期限或客户合同承诺。部署前须核对实际处理条款、服务启用、最小 RAM 权限和供应商侧删除流程，再填写披露。尚未给卜卜配置生产检测凭证，也未传输家庭原照片。
