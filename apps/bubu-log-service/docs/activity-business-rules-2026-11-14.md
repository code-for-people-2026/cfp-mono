# 卜卜日记活动业务规则与强制选择题追问

确认日期：2026-11-14（Australia/Perth）。状态：用户已确认并留档；批准规则原文保留。当前开发树已据此实现并加入自动化测试，尚未部署或完成目标手机真机验收。

关联需求：[#395 程序内对话](https://github.com/code-for-people-2026/cfp-mono/issues/395)、[#393 录入](https://github.com/code-for-people-2026/cfp-mono/issues/393)。

本文是本轮业务决策的完整基线。与旧版接口文档、验收说明或实现中的必填、默认、追问规则不一致时，以本文为准。以下批准规则作为归档原文保留；文末仅更新当前实现与验收状态。

## 1. 共同记录规则

- 先从消息和已确认的上下文识别活动。类型或信息已明确，不要求重复选择；确有歧义时只提供相关选项，不展示全部活动让用户重新分类。
- 没有提时间，采用原消息发送时间。微信异步汇总使用微信群原消息时间，直接聊天使用当前消息时间，不能使用汇总执行时间或当前浏览的日历日期。
- 明确的日期、时间和开始／结束语义优先。完成型报告使用消息时间作为完成时间，开始型报告使用消息时间作为开始时间。明确说“昨天”等时不能套成今天。
- 一个事件对应一个步骤，同一事件的多个必要缺项集中补齐；多个事件分别展示。信息完整直接记录，不生成追问。
- 后续消息补充、更正原事件；已补齐的问题自动消失。跨消息关联须确认属于同一事情，不随意合并。
- 只追问必要信息。可选信息缺失不生成问题，业务默认可以解决的项目直接采用默认。明确不知道后保留未知，不反复催问，不转成零、否或默认值。
- 原消息默认折叠；点击后展示相关发言人、发送时间及完整原文，多条来源都可查看。
- 完整性、默认、统计与事实由统一记录／MCP 业务规则维护。前端和 AI 总结不另建事实账本，继续遵守既有身份、来源、版本和权限边界。

## 2. 时间规则

亲喂、睡眠、抬头、户外需要保留持续时长。开始时间、结束时间、持续时长三者已知任意两个，即可自动计算第三个，不再追问。

| 表达 | 已知 | 自动计算 |
| --- | --- | --- |
| 2 点开始睡，睡了两个小时 | 开始＋时长 | 4 点结束 |
| 从 2 点睡到 4 点 | 开始＋结束 | 持续两小时 |
| 4 点醒了，睡了两个小时 | 结束＋时长 | 2 点开始 |
| 醒了，睡了两个小时，没有其他时间说明 | 消息时间作为结束＋时长 | 倒推开始 |
| 刚开始睡 | 开始及进行中状态 | 不提前要求尚未发生的结束时间 |

跨夜结合日期计算；三个值相互矛盾或日期确有歧义才核对。计算所得时间与原文、消息时间默认的来源应可区分。其他活动不强问时长，用户主动提供则保留。

## 3. 全部 15 类活动

以下追问均以消息及关联记录尚未提供必要信息为前提。

| 活动 | 必要信息 | 默认、可选与追问规则 |
| --- | --- | --- |
| 亲喂 BREASTFEED | 时间三选二，保留时长 | 缺少计算所需信息才问。奶量、拍嗝、乳房状态可选；明确报告摄入克数则保留，不擅自换算成毫升 |
| 瓶喂 BOTTLE（一餐可含多种奶品） | 喝完时间＋每项奶品及其实际喝入量 | 一餐只记一个事件，按原话顺序保存一个或多个奶品明细。支持母乳、配方奶及“羊奶”等无法诚实映射枚举的原话；不得把羊奶强行归为配方奶或鲜奶。未提时间用消息发送时间。不强问开始、时长、泡好量、剩余量、拍嗝。明确同一瓶且提供泡好量与剩余量时仍可计算该项实际喝入量；泡好量本身不等于喝入量 |
| 吸奶／泵奶 PUMP | 完成时间＋泵出奶量 | 时长可选，不强问；泵出量不计入宝宝实际喝入量 |
| 睡眠 SLEEP | 时间三选二，保留时长 | “睡着了”记开始，“醒了”结束对应睡眠。缺少计算所需信息或关联确有歧义才问；跨夜仍是一段睡眠 |
| 换尿布 DIAPER | 发生时间 | 默认有尿、无便、尿量大。明确提到大便或其他情况时覆盖对应默认；大便没特殊说明，不追问颜色等细节。“未说明异常”不等于明确观察到黄色 |
| 抬头 HEAD_LIFT | 时间三选二，保留时长 | 缺少计算所需信息才问，提供时长快捷选项 |
| 被动操 PASSIVE_EXERCISE | 发生时间 | “做了被动操”即可记录，不强问时长、组数 |
| 排气操 GAS_EXERCISE | 发生时间 | “做了排气操”即可记录，不强问时长、组数 |
| 洗澡 BATH | 完成时间 | “洗完澡了”即可记录，不追问时长 |
| 户外 OUTDOOR | 时间三选二，保留时长 | 缺少计算所需信息才问。“回来了，出去半小时”可用消息时间作为结束并倒推开始；地点、内容可选 |
| 早教 EARLY_EDUCATION | 发生时间 | “做了早教”即可记录；项目、时长可选，不强问 |
| 翻身 ROLL_OVER | 发生时间 | 未说次数就不填次数，记录为未量化练习；次数不必填，不默认 1、不追问。明确次数则保留 |
| 拉坐 PULL_TO_SIT | 发生时间 | 与翻身一致，可以只记录练习发生过；次数可选，不默认、不强问 |
| 补剂 SUPPLEMENT | 服用时间＋补剂种类 | 种类已明确直接记录，缺失且无法确定才问；剂量、品牌暂不新增为必填 |
| 吐奶 SPIT_UP | 发生时间 | 默认普通吐奶；特殊描述覆盖默认，不每次询问吐奶类型 |

翻身、拉坐记录了一次练习事件，不代表动作做了 1 次。未提供动作次数时保持未量化，次数统计不能按 1 累计，也不能折算为 0。

## 4. 强制选择题，不是“优先选择题”

用户最终要求：每个需要用户回答的追问都必须是选择题；正式回复前检查，不符合就要求重新生成。

- 所有活动缺项、类型歧义、时间矛盾、重复核对等要求用户作答的追问，都必须提供对应的可点击选项。
- 奶量、时长、次数等数值问题使用宝宝的常用选项，紧凑排列在一行，最后提供“自定义”。默认不出现空输入框，点击自定义后才展开具体值输入或时间选择。
- 需要自定义回答的问题必须提供自定义入口，不能仅靠“请填写／请描述”代替选择题；也不能只放一个“自定义”而省略有意义的常用选择。
- 适用时提供“不知道”“仍在进行”等选项。用户仍可直接聊天作答，强制要求约束的是助手发出的追问形式。
- 同一事件的多个问题仍放在同一步，不拆成一题一步。
- 业务默认值可以直接生效；快捷选项只是便捷回答，未被选择不能成为本次事实。次数选项的存在不改变翻身、拉坐次数可选的规则。
- 记录回执、查询结果、规律总结等不要求用户回答的说明可以正常陈述；其中只要夹带追问，那一问也必须有选项。

### 正式回复前的校验与重新生成

这是发送前的硬性验收门槛，不能只靠提示词要求模型自觉遵守。

1. 检查完整待发送回复中的每一个追问，包含说明文字、结尾追问和表单问题，以及对应的可渲染选项。
2. 任何追问没有有效选项，或把填空作为默认回答方式，整份回复不得直接展示；反馈具体不合格项，要求重新生成。
3. 重新生成的回复再次检查，全部通过后才正式发送。不能先流出不合格问题再补救，也不能在重试失败时降级发送原填空题。
4. 检查覆盖所有用户可见的追问出口，包括模型文本、服务端拼接提示、历史待补展示，避免模型合格但服务端又追加开放式问题。
5. 重新生成的是回复内容，不重放已经完成的记录写入、工具副作用或配置修改；继续使用已有可靠回执。
6. 具体重试上限与失败呈现方式留待实现设计，但任何失败处理都不能绕过选择题校验。

## 5. 常用选项只属于宝宝

- 每个宝宝独立维护一套配置，所有照护者共用。没有“我的选项”、个人覆盖或用户／宝宝两级优先级。
- 奶量、各活动时长、次数、户外时长等分别配置；同一宝宝不同活动可使用不同数值档位。
- 设置页支持增删、修改数值、调整顺序；与 AI 聊天也能修改同一套配置，修改结果明确反馈。
- “这次喝了 210 ml”只记录事件；“把 210 ml 加入常用选项”才修改配置。
- 数值示例不视为所有宝宝的固定选项或喂养建议。

## 6. 首次使用一周后的自动规律总结

- 首次使用满一周，按该宝宝实际记录自动总结常见奶量、时长、次数等，在聊天历史中留下可回看结果，用户上线后可见。
- 说明数据时间范围、发现的规律、整理出的快捷选项，以及通过聊天或设置页继续调整的方法。
- 只使用实际已确认的数据。未知值、尚未完成的时长、未量化次数，以及业务默认填入的值，不作为实际习惯依据；数据不足明确说明，不凑选项。
- 未手动配置的项目可以自动生成选项并告知；已手动配置的项目，AI 提建议，不静默覆盖。调整建议如果要求用户作答，也必须通过选择题校验。
- 后续定期总结频率尚未规定；本次不额外创建现实中的提醒或自动化任务。
- 总结宝宝共享的照护事实，不向其他照护者泄露私人聊天历史。

## 7. 实现验收场景（自动化已纳入，真机待验收）

- 三种等价时间表达得到同一范围与时长，不额外追问；跨夜日期正确。
- 奶粉／母乳“喝完 180 ml，未提时间”按消息时间记录，不问起止、时长或泡好量。
- “晚上喝奶 200 羊奶，150 奶粉”只生成一餐、一个 BOTTLE 事件、两个奶品明细：原话“羊奶”200ml 与 FORMULA 150ml；全部明细已知时派生整餐合计350ml，不追问奶源、奶量或时间。
- 同餐同种奶续喝可保留为另一条明细；明确说两餐才创建两个事件。时间接近不是合并依据，真正无法判断餐次时只用带选项的核对题。
- 只有一项奶量缺失时，同一事件表单只显示该项的奶量控件；常用奶量选项与“自定义”均绑定稳定明细 ID，全部草稿留在本机直到一次批量提交。
- “换尿布了”得到有尿、无便、尿量大，无追问；提到大便但没有颜色，不追问或伪造具体颜色。
- 翻身／拉坐没有次数仍可完整记录，次数保持未量化；普通吐奶直接使用默认。
- 只有亲喂、睡眠、抬头、户外要求完成时长；其他活动不因缺少时长产生待补。
- 数值追问默认显示可点击常用选项及自定义，输入框只在选择自定义后出现。
- 故意生成“喝了多少？”而无选项，或在合格表单后追加无选项追问，必须被发送前检查拦截并重新生成；重新生成不重复写记录。
- 修改一个宝宝的选项，其照护者看到同一配置；其他宝宝不受影响，不出现个人选项。
- 满一周总结不将默认值或未量化次数当成真实习惯，不静默覆盖手动配置，并持久显示总结及调整入口。

## 8. 与现有实现的差异及范围

当前开发树已按本文收敛活动完整性与统计规则，接入宝宝共享常用选项、版本化设置与聊天修改、持久首周总结，以及覆盖模型文本、服务端问题和历史展示的发送前选择题校验。HTTP → Payload → MCP → 受控 provider 的浏览器夹具和聚焦单元／集成测试用于验证这些边界；这不构成部署、真实 provider 质量或手机真机验收声明。

旧规则中“禁止套用旧表单默认值”应细化为：禁止将便捷选项伪装成事实，同时允许本文明确授权的业务默认。本文不改变既有事实权限、回执、幂等性和私人对话隔离要求。

## 2026-11-15 手机验收修订

- 已明确奶品、实际奶量的消息直接记录；未提时间沿用原消息时间。同一次瓶喂中的“羊奶 200ml、奶粉 70ml”是一餐、一个事件、两个奶品明细，整餐合计270ml；羊奶按原话保留，不擅自判成配方奶或鲜奶。明确表达为两餐时才分别记录。
- 全系统仍按北京时间处理日期和时间，展示时不再重复附加“上海时间”或“北京时间”。
- 原消息优先展示真实昵称与可用头像；缺失时使用中性称呼和占位头像，不展示内部账号 ID，不虚构姓名或照片。
- 移除字段旁通用的“不知道”快捷按钮。选择题保留“自定义”；用户明确说不知道时，后台仍保留未知状态、不反复追问。
- 自定义及“补充说明”输入留在当前事件表单内，不转移到底部聊天输入框。同一个保存动作提交已选选项和自定义内容，保留各字段语义和原事件版本。
- 自定义日期与时间控件之间，以及控件与上方选项之间，需要明确间距。
- 本次构造的待补充案例放在当前宝宝下，明确标注“测试记录”；真实记录修正与测试案例分开处理。

## 2026-11-15 多奶品一餐规则更新（当前）

- 新建 BOTTLE 事实以有稳定且事件内唯一 `id` 的 `milkItems` 为唯一可编辑奶品权威；每项含奶源枚举或原话奶品、实际喝入量及逐项状态。重复 ID、非法数量、非有限数、负数、越权增删或调序都整体拒绝。
- 根 `milkAmount` 只在所有明细奶量均为已知时由服务端派生，不能作为新瓶喂输入或第二个可编辑权威。部分已知时只显示“已知小计（非整餐总量）”，未知项不估算；已知0、待补和明确未知保持不同语义。
- 新的喂养候选在用户确认类型为 BOTTLE 时创建一个稳定初始奶品明细，并把该候选阶段已知的奶品或奶量事实转入该明细；这属于当前新事件的类型澄清，不是旧瓶喂记录转换。
- 待补回答只允许更新当前问题绑定的明细 ID 和字段；客户端不能用整个数组覆盖已知兄弟项，服务端同时核对问题版本、事件版本、数组身份与顺序。混合批次中任一非法项导致整批不写入。
- sidecar `care-events` 继续是权威记录。旧 Activity 每餐只投影一行和完整时的派生总量；旧核心表不接收嵌套明细，详情与授权快照从 sidecar 返回明细。投影漂移时不得用 sidecar 明细掩盖外部核心修改。
- 本更新不迁移、回填、重放或改写历史瓶喂，也不提供旧标量瓶喂转换适配器。没有 `milkItems` 的旧标量 BOTTLE 只读保留：不显示其旧字段待补表单，任何需要按新规则重新求值或接受旧投影的修改都在写入前失败关闭，原事实、版本与投影不变；明确撤销仍可保留为不重算事实的元数据操作。两个旧的一次性拆分事件验收维护入口已停用并在任何模式下先于写入失败关闭，旧实现仅留作归档。
- 当前范围只覆盖瓶喂一餐多奶品。亲喂继续使用原有时间三选二规则，PUMP 继续使用根泵出奶量；“亲喂＋瓶喂加餐”作为一餐分组仍是未来工作，不新增 FEEDING 活动类型，也不把亲喂分钟或泵奶量折算成喝入毫升。
