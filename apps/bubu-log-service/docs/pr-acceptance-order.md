## 每项通过后的操作

1. 对照该 PR 相对目标分支的差异，并记录本次实际测试版本、通过项和未测项。
2. 用户明确确认当前 PR 验收通过，再合并当前 PR；不批量合并后续 PR。
3. 处理下一个 PR 的目标分支和必要的同步，确认只剩该模块新增差异；若采用 squash，须先处理后续分支的提交依赖，避免重复带入整条历史。
4. 真机体验用于验证集成效果；后台权限、采集重放和恢复删除等仍需对应证据。微信认证、备案、隐私指引和正式审核另行记录，不从代码合并推断平台已批准。
