# 卜卜日记

产品展示名为「卜卜日记」。日历可视化与程序内对话均在 `cfp-mono` 实现。客户端采用本仓库的 Taro 技术栈；数据仍由 `sunmer-home/apps/bubu-log` 的既有 Payload CMS 后端维护。业务数据的集合、字段和统计逻辑保持原样，不迁移数据库；独立身份与照护授权由卜卜日记服务负责。

## Candidate boundaries

**#438 独立候选**：只代表手势、记录来源、月历四环和本机参考设置这条可视化演进线，验收时应先在其原始基线和范围内完成评审与自动化检查。**集成体验候选**：把 #438 与已存在的旧账号、独立身份、微信/sidecar、监护人、家庭邀请、会员和隐私能力合并后再验收；集成结果不能反向替代 #438 的独立验收。验收顺序为 #438 独立候选通过后，再完成集成候选的全量检查与目标环境验收；文档本身不声明部署或真机结果。

## Language

**宝宝访问上下文**：原后端根据登录用户与 BabyUser 关系核验的宝宝及可访问宝宝列表。每个读取请求明确携带当前宝宝，切换时清除旧视图和详情。

**照护记录**：原 Activity，包括睡眠、尿布、亲喂、瓶喂、吸奶和其他全部 15 类活动。界面显示原字段，不发明来源、待补状态或不存在的喂养数据。

**每日统计**：兼容模式读取后端已保存的 DailyStat，趋势缺失代表没有统计快照而不是活动为零；首页与记录列表沿用旧 Activity 摘要口径。独立身份模式使用统一记录服务的实际事实投影：首页 `/records/snapshot` 与趋势、热力图同源，保留原指标字段，另外读取完整性覆盖信息。未知不作为零、进行中不作为完成时长、疑似重复不双计；没有记录不表示实际没有发生。月历四环只在展示层组合瓶喂量、睡眠时长、尿布次数、亲喂和户外，不重算或写回 DailyStat。

**日历地图**：日时间轴、七列周历与自然月四环组成的可视化；不是地理位置地图。日轴是默认首页。中央标题使用上海日历的相对名称（今日／昨日／前日、本周／上周、本月／上月），周从周一开始，月历只展示完整自然月。

**月历四环**：吃为已保存瓶喂量加亲喂参考估计，睡为已保存睡眠时长，玩为户外时长，便为全部换尿布次数。亲喂优先已有奶量，否则按有效时长与可调整速度估计；未知、未结束或不完整的记录不充当零。户外按日截断并合并重叠，家庭目标为 1／2／3 小时，尿布家庭目标为 6 次。奶量和睡眠采用记录当日月龄参考或本机自定义区间。满环不表示越多越好；来源与计算边界见 [参考资料](docs/care-ring-references.md)。

**本机参考设置**：亲喂初始 5–10 ml/分钟是粗略展示估计，可修改或关闭；设置只保存在本机，不同步给家人。后续 MCP/chat 将直接接受用户上报的克数（#439、#440）。

**旧账号登录**：显式兼容模式复用 NextAuth 的用户名/密码会话。独立身份模式用旧凭证验证原用户，完成身份交换/绑定；凭证不交给模型，也不在客户端持久化。

**微信身份**：独立身份服务验证 `wx.login` 的 code 后建立的身份，与旧账号绑定状态、当前宝宝和照护授权分别处理。昵称不是身份凭证。

**照护邀请码**：服务端签发的有限期加入凭证。加入成功的照护者无需绑定旧账号，即可查看被授权宝宝；每个后续业务请求仍由服务端核验权限。

**独立身份模式**：`BUBU_AUTH_MODE=sidecar` 选择卜卜日记服务。微信使用按 origin 隔离的 Bearer token，H5 使用同源 HttpOnly Cookie；`sidecar` 为默认模式，显式 `legacy` 保留原部署路径。

**记录来源**：活动详情中默认折叠的「更多信息」，只读展示旧服务 `GET /api/app/audits` 里成功 CREATE 该活动的现有字段：记录账号 ID（不是姓名）、TEXT/语音录入方式、添加时间和原话。选中记录必须携带与请求完全一致的宝宝 ID；缺失、null 或跨宝宝记录不作为本家庭证据。旧审计不提供人类展示名，也不能区分小程序或微信群入口；活动备注不是原话，缺失来源用普通文案和重试表达。

## Module boundaries

可视化负责读取、筛选、排序、可视化和只读照护记录详情；设置页宝宝资料复用原 `PATCH /api/app/user-babies/:id` 修改宝宝昵称（name）和姓名（fullName），照护参考只按后端地址与宝宝 ID 保存在本机，均不创建后端字段或改动权限。月历经现有 `GET /api/app/baby-profile?babyId` 读取生日，按记录日期计算月龄；读取失败保留数据、明确年龄参考不可用，401 则结束当前会话。`src/api` 隔离旧协议，`src/model` 保留展示与摘要规则，`src/components` 可视化组件不持有写入能力；`IdentitySetup` 独立承载身份、家庭创建/绑定/邀请引导，页面负责宝宝、日期和选择状态。活动详情的创建/更新元数据收进默认折叠的「更多信息」；只在用户首次展开时读取有界审计页，关闭、切换宝宝或会话变化会丢弃迟到结果。旧模式照片 URL 原样读取；独立身份模式改为鉴权媒体读取。

首页沿用 Hello Agent 的自定义顶栏和左侧抽屉。左上角宝宝头像右下角带菜单标记，头像缺失或加载失败使用无边框品牌图标；中间日期点击后展开日／周／月、选择日期与回到今天，左右箭头切换相应时段。顶栏按微信状态栏和胶囊位置留白，小屏使用双行日期；滚动意图会让摘要与顶栏收起或复原。八个紧凑摘要与昨晚衔接在前，时间轴直接铺开，不带外层卡片和教学文案。日／周时间轴共享右滑前一段／左滑后一段、顶部下拉前一段／底部上拉后一段和双指垂直捏合缩放；普通单指纵向滚动仍由原生 ScrollView 承担。翻页按触点连续跟随：横向或纵向拖动的交叉位移决定纸页角度，首次触点作为卷曲支点，边缘阴影随进度加深，松开后由过渡完成或回弹。相邻页预渲染，翻页交互只改变展示几何，不改变数据读取或写入。菜单顺序为日历、历史记录、趋势、设置；切换入口保留浏览日期。周历点击日期和月历查看当天均进入未筛选的日历，两者均能返回原时段。宝宝切换、刷新及退出也在菜单内；设置为独立子页面，返回保留浏览日期与视图，昵称保存后同步菜单。头像上传由后续私有媒体能力接入，本层仅展示已有头像。

用户已指定另外五个模块：Agent/MCP 录入、程序内对话、微信小程序认证、Payload CMS 运营、付费会员。内置对话读取持久化的待补事项，围绕当前宝宝持续会话；不接入通用祝福会话或 Hello Agent 的领域模型，不建立固定录入表单。首期产品限时免费的安排仍以 PRD 为准。

详细产品要求与实施顺序在 [MVP PRD](https://github.com/code-for-people-2026/cfp-mono/issues/391)、[六模块规划](https://github.com/code-for-people-2026/cfp-mono/issues/392) 和 [可视化模块](https://github.com/code-for-people-2026/cfp-mono/issues/394)，运行与迁移边界见 [README](README.md)。

身份模块新增登录恢复、退出、旧凭证绑定、首次创建宝宝与照护邀请码加入；不会把宝宝事实写进聊天文本。撤权/失效清除当前视图，迟到响应不恢复旧上下文。独立身份模式的照片在打开详情时经服务端鉴权读取，微信临时文件随详情/宝宝/身份变化清理。接口与测试方法见 README；可信 Agent、群绑定和运营权限由服务端契约约束，客户端不可声明自己的角色。

录入模块的可视化接缝仅提供只读信息：详情显示来源类型与时间、版本、待补字段和关联私有图片，不保留来源账号、群、发送者或消息标识用于展示；首页同步提示单独展示最近成功、处理进度、媒体待补和失败状态。同步状态失败不等同于没有活动。内置聊天通过服务端 Agent 调用统一 MCP 工具处理录入、补充、更正、删除与撤销；客户端不直接操作事实。草稿与未确认发送独立持久化，并以结构化回执驱动事实刷新。

**宝宝服务状态**：同一宝宝的所有授权照护者共享的免费体验和服务权益，由独立服务唯一判定。菜单打开时读取 `/api/app/membership`，只展示服务端状态、说明和已配置的起止时间，不按客户端时间推断到期。读取失败明确显示暂不可读，不能回退为免费授权。暂停或到期不隐藏历史；兼容模式不调用此独立服务接口。首期没有购买、账单或支付调用入口。

菜单内的**隐私与安全**承载本人和监护人授权、数据权利、投诉与处理进度；隐私界面不会绕过 MCP 录入照护事实。首次授权与政策更新有明确选择，所有开关默认关闭；图片先请求微信隐私能力，再由服务器判断用途与宝宝授权。AI 回复与固定系统安全提示区别标识。删除受理不等于清理完成，状态以服务器回执为准。
