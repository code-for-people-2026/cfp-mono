# 卜卜日记

产品展示名为「卜卜日记」。当前实施阶段是把原宝宝日记的可视化迁入 `cfp-mono`。客户端采用本仓库的 Taro 技术栈；数据仍由 `sunmer-home/apps/bubu-log` 的既有 Payload CMS 后端维护。此阶段保持集合、字段、权限和统计逻辑，不迁移数据库。

## Language

**宝宝访问上下文**：原后端根据登录用户与 BabyUser 关系核验的宝宝及可访问宝宝列表。每个读取请求明确携带当前宝宝，切换时清除旧视图和详情。

**照护记录**：原 Activity，包括睡眠、尿布、亲喂、瓶喂、吸奶和其他全部 15 类活动。界面显示原字段，不发明来源、待补状态或不存在的喂养数据。

**每日统计**：后端已保存的 DailyStat。趋势读取其原始数值，缺失代表没有统计快照，不代表活动为零。首页与记录列表的 Activity 摘要分别沿用旧口径。月历四环复用已保存瓶喂量、睡眠时长与尿布次数，另从当月 Activity 读取亲喂和户外；只在展示层组合，不重算或写回 DailyStat。

**日历地图**：日时间轴、七列周历与自然月四环组成的可视化；不是地理位置地图。日轴是默认首页。中央标题使用上海日历的相对名称（今日／昨日／前日、本周／上周、本月／上月），周从周一开始，月历只展示完整自然月。

**月历四环**：吃为已保存瓶喂量加亲喂参考估计，睡为已保存睡眠时长，玩为户外时长，便为全部换尿布次数。亲喂优先已有奶量，否则按有效时长与可调整速度估计；未知、未结束或不完整的记录不充当零。户外按日截断并合并重叠，家庭目标为 1／2／3 小时，尿布家庭目标为 6 次。奶量和睡眠采用记录当日月龄参考或本机自定义区间。满环不表示越多越好；来源与计算边界见 [参考资料](docs/care-ring-references.md)。

**本机参考设置**：亲喂初始 5–10 ml/分钟是粗略展示估计，可修改或关闭；设置只保存在本机，不同步给家人。后续 MCP/chat 将直接接受用户上报的克数（#439、#440）。

**旧账号登录**：过渡期复用 NextAuth 的用户名/密码会话；不是 `wx.login`。后续微信身份认证由独立模块提供。

**记录来源**：活动详情中默认折叠的「更多信息」，只读展示旧服务 `GET /api/app/audits` 里成功 CREATE 该活动的现有字段：记录账号 ID（不是姓名）、TEXT/语音录入方式、添加时间和原话。选中记录必须携带与请求完全一致的宝宝 ID；缺失、null 或跨宝宝记录不作为本家庭证据。旧审计不提供人类展示名，也不能区分小程序或微信群入口；活动备注不是原话，缺失来源用普通文案和重试表达。

## Module boundaries

当前模块负责读取、筛选、排序、可视化和只读照护记录详情；设置页复用原 `PATCH /api/app/user-babies/:id` 修改宝宝昵称（name）和姓名（fullName）；照护参考只按后端地址与宝宝 ID 保存在本机，不创建后端字段或改动权限。月历经现有 `GET /api/app/baby-profile?babyId` 读取生日，按记录日期计算月龄；读取失败保留数据、明确年龄参考不可用，401 则结束当前会话。`src/api` 隔离旧协议，`src/model` 保留展示与摘要规则，`src/components` 不持有写入能力，页面负责宝宝、日期和选择状态。活动详情的创建/更新元数据收进默认折叠的「更多信息」；只在用户首次展开时读取有界审计页，关闭、切换宝宝或会话变化会丢弃迟到结果。现有照片 URL 原样读取与预览。

首页沿用 Hello Agent 的自定义顶栏和左侧抽屉。左上角宝宝头像右下角带菜单标记，头像缺失或加载失败使用无边框品牌图标；中间日期点击后展开日／周／月、选择日期与回到今天，左右箭头切换相应时段。顶栏按微信状态栏和胶囊位置留白，小屏使用双行日期；普通单指纵向滚动只收起或恢复摘要与昨晚衔接，日期与头像导航保持可见。八个紧凑摘要与昨晚衔接在前，时间轴直接铺开，不带外层卡片和教学文案。日／周时间轴共享左滑后一段／右滑前一段和双指垂直捏合 0.5–3× 缩放；只有横向滑动触发翻页，所有单指纵向移动（包括到达上下边界）都保持原生 ScrollView 滚动。翻页使用原页、底页和正文保持原位的预计算折页几何表；原生事件绑定在持续存在的外层 `PaperTurnViewport`，不动态切换 `catchMove`，捏合时用 enhanced ScrollView 的 `scrollEnabled` 锁定滚动。相邻页预渲染，翻页交互只改变展示几何，不改变数据读取或写入。菜单顺序为日历、历史记录、趋势、设置；切换入口保留浏览日期。周历点击日期和月历查看当天均进入未筛选的日历，两者均能返回原时段。宝宝切换、刷新及退出也在菜单内；设置为独立子页面，返回保留浏览日期与视图，昵称保存后同步菜单。头像上传由后续私有媒体能力接入，本层仅展示已有头像。

用户已指定另外五个模块：Agent/MCP 录入、程序内对话、微信小程序认证、Payload CMS 运营、付费会员。内置对话及待补事项后续融合，当前不接入通用祝福会话或 Hello Agent 的领域模型；不建立占位字段或固定录入表单。首期产品限时免费的安排仍以 PRD 为准。

详细产品要求与实施顺序在 [MVP PRD](https://github.com/code-for-people-2026/cfp-mono/issues/391)、[六模块规划](https://github.com/code-for-people-2026/cfp-mono/issues/392) 和 [可视化模块](https://github.com/code-for-people-2026/cfp-mono/issues/394)，运行与迁移边界见 [README](README.md)。
