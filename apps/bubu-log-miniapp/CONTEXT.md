# 卜卜日记

产品展示名为「卜卜日记」。日历可视化与程序内对话均在 `cfp-mono` 实现。客户端采用本仓库的 Taro 技术栈；兼容模式仍由 `sunmer-home/apps/bubu-log` 的既有 Payload CMS 后端维护。业务集合、字段、权限和统计逻辑不迁移数据库；独立身份与照护授权由卜卜日记服务负责。

2026-11-14 已确认的业务基线见[活动业务规则与强制选择题追问](../bubu-log-service/docs/activity-business-rules-2026-11-14.md)。当前开发树已实现可点击追问、自定义后显示输入、宝宝共享常用选项、首周通知及服务端发送前检查／重新生成；已发布到体验版 0.3.7；一餐多奶品与原消息场景已获用户手机确认，完整验证边界见[验证记录](../bubu-log-service/docs/activity-rules-validation-2026-11-15.md)。

## Candidate boundaries

**#438 独立候选**：只代表手势、记录来源、月历四环和本机参考设置这条可视化演进线，验收时应先在其原始基线和范围内完成评审与自动化检查。**集成体验候选**：把 #438 与已存在的旧账号、独立身份、微信/sidecar、监护人、家庭邀请、会员和隐私能力合并后再验收；集成结果不能反向替代 #438 的独立验收。验收顺序为 #438 独立候选通过后，再完成集成候选的全量检查与目标环境验收；文档本身不声明部署或真机结果。

## Language

**宝宝访问上下文**：原后端根据登录用户与 BabyUser 关系核验的宝宝及可访问宝宝列表。每个读取请求明确携带当前宝宝，切换时清除旧视图和详情。

**照护记录**：原 Activity，包括睡眠、尿布、亲喂、瓶喂、吸奶和其他全部 15 类活动。界面显示原字段，不发明来源、待补状态或不存在的喂养数据。

**瓶喂一餐与奶品明细**：新的瓶喂记录一餐只显示一个日历／历史事件，可包含多个有稳定 ID 的奶品明细；详情和聊天回执逐项显示真实奶品与实际喝入量。只有全部项已知才显示整餐合计；有未知项时显示“已知小计（非整餐总量）”。客户端逐项解码并用 `milkItemId` 保存草稿，不能用数组覆盖、增删或调序服务端兄弟项。

**每日统计**：兼容模式读取后端已保存的 DailyStat，趋势缺失代表没有统计快照而不是活动为零；首页与记录列表沿用旧 Activity 摘要口径。独立身份模式使用统一记录服务的实际事实投影：首页 `/records/snapshot` 与趋势、热力图同源，保留原指标字段，另外读取完整性覆盖信息。未知不作为零、进行中不作为完成时长、疑似重复不双计；没有记录不表示实际没有发生。月历四环复用已保存瓶喂量、睡眠时长与尿布次数，并从当月 Activity 读取亲喂和户外；只在展示层组合，不重算或写回 DailyStat。

**日历地图**：日时间轴、七列周历与自然月四环组成的可视化；不是地理位置地图。日轴是默认首页。中央标题使用上海日历的相对名称（今日／昨日／前日、本周／上周、本月／上月），周从周一开始，月历只展示完整自然月。

**月历四环**：吃为已保存瓶喂量加亲喂参考估计，睡为已保存睡眠时长，玩为户外时长，便为全部换尿布次数。亲喂优先已有奶量，否则按有效时长与可调整速度估计；未知、未结束或不完整的记录不充当零。户外按日截断并合并重叠，家庭目标为 1／2／3 小时，尿布家庭目标为 6 次。奶量和睡眠采用记录当日月龄参考或本机自定义区间。满环不表示越多越好；来源与计算边界见 [参考资料](docs/care-ring-references.md)。

**本机参考设置**：亲喂初始 5–10 ml/分钟是粗略展示估计，可修改或关闭；设置只保存在本机，不同步给家人。当前 MCP 记录（#439）支持可选 `reportedIntake`（数值 `value`、单位 `g` 和必填原话 `originalText`），sidecar 只读详情将其作为明确报告展示。月历的亲喂速度估计单独标识，报告克数不换算或参与该估计，本层也没有称重或校准表单。

**记录常用选项**：独立于本机参考设置的宝宝共享配置页。奶量、各活动时长与次数按活动编辑，支持增删、改值和排序；保存使用观察版本，冲突时刷新服务端版本但保留本地草稿并明确提示。宝宝或身份变化清空旧响应。聊天表单只把这些值当成可点快捷回答，默认不展开输入，也不自动选中。

**旧账号登录**：显式兼容模式复用 NextAuth 的用户名/密码会话；不是 `wx.login`。独立身份模式用旧凭证验证原用户，完成身份交换/绑定；凭证不交给模型，也不在客户端持久化。

**微信身份**：独立身份服务验证 `wx.login` code 后建立的身份，与旧账号绑定、当前宝宝和照护授权分别处理。昵称不是身份凭证。

**照护邀请码**：服务端签发的有限期加入凭证。加入成功的照护者无需绑定旧账号，即可查看被授权宝宝；后续业务请求仍由服务端核验权限。

**独立身份模式**：`BUBU_AUTH_MODE=sidecar` 选择卜卜日记服务。微信端使用按服务 origin 隔离的 Bearer token，H5 使用同源会话；`sidecar` 为默认模式，显式 `legacy` 保留原部署路径。

**记录来源**：活动详情中默认折叠的「更多信息」，只读展示旧服务 `GET /api/app/audits` 里成功 CREATE 该活动的现有字段：记录账号 ID（不是姓名）、TEXT/语音录入方式、添加时间和原话。选中记录必须携带与请求完全一致的宝宝 ID；缺失、null 或跨宝宝记录不作为本家庭证据。旧审计不提供人类展示名，也不能区分小程序或微信群入口；活动备注不是原话，缺失来源用普通文案和重试表达。

## Module boundaries

当前模块负责读取、筛选、排序、可视化和只读照护记录详情；设置页复用原 `PATCH /api/app/user-babies/:id` 修改宝宝昵称（name）和姓名（fullName）；照护参考只按后端地址与宝宝 ID 保存在本机，不创建后端字段或改动权限。月历经现有 `GET /api/app/baby-profile?babyId` 读取生日，按记录日期计算月龄；读取失败保留数据、明确年龄参考不可用，401 则结束当前会话。`src/api` 隔离旧协议，`src/model` 保留展示与摘要规则，`src/components` 不持有写入能力，页面负责宝宝、日期和选择状态。活动详情的创建/更新元数据收进默认折叠的「更多信息」；只在用户首次展开时读取有界审计页，关闭、切换宝宝或会话变化会丢弃迟到结果。现有照片 URL 原样读取与预览。

独立身份模式的活动详情可附加只读记录元数据：显示安全来源类型与时间、版本、保存状态、待补字段和明确未知；不再叠加旧审计账号/原话面板。关联照片只使用页面经服务端授权解析得到的临时 URL，组件不按附件 ID 或公开路径自行拼 URL；关闭详情、切换宝宝或身份变化由页面释放临时文件。首页同步状态只描述最近成功、处理进度、待补媒体与失败提醒，失败不代表没有已保存活动。

首页沿用 Hello Agent 的自定义顶栏和左侧抽屉。左上角宝宝头像右下角带菜单标记，头像缺失或加载失败使用无边框品牌图标；中间日期点击后展开日／周／月、选择日期与回到今天，左右箭头切换相应时段。顶栏按微信状态栏和胶囊位置留白，小屏使用双行日期；普通单指纵向滚动只收起或恢复摘要与昨晚衔接，日期与头像导航保持可见。八个紧凑摘要与昨晚衔接在前，时间轴直接铺开，不带外层卡片和教学文案。日／周时间轴共享左滑后一段／右滑前一段和双指垂直捏合 0.5–3× 缩放；只有横向滑动触发翻页，所有单指纵向移动（包括到达上下边界）都保持原生 ScrollView 滚动。翻页使用原页、底页和正文保持原位的预计算折页几何表；原生事件绑定在持续存在的外层 `PaperTurnViewport`，不动态切换 `catchMove`，捏合时用 enhanced ScrollView 的 `scrollEnabled` 锁定滚动。相邻页预渲染，翻页交互只改变展示几何，不改变数据读取或写入。菜单顺序为日历、历史记录、趋势、设置；切换入口保留浏览日期。周历点击日期和月历查看当天均进入未筛选的日历，两者均能返回原时段。宝宝切换、刷新及退出也在菜单内；设置为独立子页面，返回保留浏览日期与视图，昵称保存后同步菜单。头像上传由后续私有媒体能力接入，本层仅展示已有头像。

用户已指定另外五个模块：Agent/MCP 录入、程序内对话、微信小程序认证、Payload CMS 运营、付费会员。程序内对话围绕当前宝宝持续会话，通过服务端 Agent 调用统一 MCP 工具，不接入通用祝福会话或 Hello Agent 的领域模型，也不建立占位字段或固定录入表单；正式 onboarding 引导仍 deferred 到第 4 层。首期产品限时免费的安排仍以 PRD 为准。

详细产品要求与实施顺序在 [MVP PRD](https://github.com/code-for-people-2026/cfp-mono/issues/391)、[六模块规划](https://github.com/code-for-people-2026/cfp-mono/issues/392) 和 [可视化模块](https://github.com/code-for-people-2026/cfp-mono/issues/394)，运行与迁移边界见 [README](README.md)。

**程序内对话**：日历右下角进入的宝宝范围持续会话；文字、校对后的语音草稿和私有图片先按身份、宝宝与请求号保存/恢复，再由服务端委托真实 MCP 工具处理。聊天不能直接写旧 Activity、拼公开照片地址或在前端累计事实；已记录状态只来自结构化回执，收到刷新要求后重读统一投影。

**对话选择**：从记录详情进入对话时携带的事件上下文。它只用于定位待更正、删除或撤销的事实，不赋予模型权限；宝宝、来源和请求号仍由服务端运输/执行层注入。

菜单内的**隐私与安全**承载本人和监护人授权、数据权利、投诉与处理进度；隐私界面不会绕过 MCP 录入照护事实。首次授权与政策更新有明确选择，所有开关默认关闭；图片先请求微信隐私能力，再由服务器判断用途与宝宝授权。AI 回复与固定系统安全提示区别标识。删除受理不等于清理完成，状态以服务器回执为准。

对话是独立的 `/pages/chat/index` 全页路由，不再是首页底部弹层；页面保持原生导航安全区、一个历史滚动区和一个底部输入区。待补字段表单按事件分步填写，全部必填事件在本机复核后一次提交；步骤切换不写服务端。草稿和原请求号跨导航、重开与结果恢复保留，只有回执明确覆盖的事件才清理；其余答案保留并提示复核。微信群自动通知作为普通历史条目展示，展开仅在对应事件行下方读取原消息，程序内直接对话保持实时。事实仍由服务端 Agent 调用 MCP 工具确认和保存。

明确标记的手机验收测试记录也默认折叠原消息；展开后每条都显示「测试记录 · 模拟消息」、测试昵称、时间和昵称首字头像，不借用真实人物头像。客户端只接受服务端精确关联后返回的 `test` 来源，不把一般手工记录的事实或备注临时拼成原话。

同一事件的字段、时间／重复冲突和媒体选择合并在一个紧凑步骤中；喂养类型歧义只显示亲喂／瓶喂，再按需处理奶源，不展示全部活动。历史中的首周规律是独立宝宝共享通知，不伪装成用户、采集者或私人助手消息。`firstWeekNotice` 随历史加载保留在会话状态，新轮次、刷新和轮询只更新当前宝宝对应值。

**对话选择**：从记录详情进入对话时携带的事件上下文。它只用于定位待更正、删除或撤销的事实，不赋予模型权限；宝宝、来源和请求号仍由服务端运输/执行层注入。
