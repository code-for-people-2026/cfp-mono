# 哺哺日记

产品展示名为「哺哺日记」。当前实施阶段是把原宝宝日记的可视化迁入 `cfp-mono`。客户端采用本仓库的 Taro 技术栈；数据仍由 `sunmer-home/apps/bubu-log` 的既有 Payload CMS 后端维护。业务数据的集合、字段和统计逻辑保持原样，不迁移数据库；独立身份与照护授权由哺哺日记服务负责。

## Language

**宝宝访问上下文**：原后端根据登录用户与 BabyUser 关系核验的宝宝及可访问宝宝列表。每个读取请求明确携带当前宝宝，切换时清除旧视图和详情。

**照护记录**：原 Activity，包括睡眠、尿布、亲喂、瓶喂、吸奶和其他全部 15 类活动。界面显示原字段，不发明来源、待补状态或不存在的喂养数据。

**每日统计**：后端已保存的 DailyStat。趋势和热力图读取其原始数值，缺失代表没有统计快照，不代表活动为零。首页与记录列表的 Activity 摘要分别沿用旧口径，不与 DailyStat 合并计算。

**日历地图**：日时间轴、七列周历与近四周热力图组成的可视化；不是地理位置地图。日轴是默认首页。

**旧账号登录**：默认兼容模式复用 NextAuth 的用户名/密码会话。独立身份模式用旧凭证验证原用户，完成身份交换/绑定；凭证不交给模型，也不在客户端持久化。

**微信身份**：独立身份服务验证 `wx.login` 的 code 后建立的身份，与旧账号绑定状态、当前宝宝和照护授权分别处理。昵称不是身份凭证。

**照护邀请码**：服务端签发的有限期加入凭证。加入成功的照护者无需绑定旧账号，即可查看被授权宝宝；每个后续业务请求仍由服务端核验权限。

**独立身份模式**：`BUBU_AUTH_MODE=sidecar` 选择哺哺日记服务。微信使用按 origin 隔离的 Bearer token，H5 使用同源 HttpOnly Cookie；`legacy` 默认模式保留原部署路径。

## Module boundaries

可视化负责读取、筛选、排序、可视化和只读照护记录详情；设置页宝宝资料复用原 `PATCH /api/app/user-babies/:id` 修改宝宝昵称（name）和姓名（fullName），不创建字段或改动后端权限。`src/api` 隔离旧协议，`src/model` 保留展示与摘要规则，`src/components` 可视化组件不持有写入能力；`IdentitySetup` 独立承载身份引导，页面负责宝宝、日期和选择状态。旧模式照片 URL 原样读取；独立身份模式改为鉴权媒体读取。

首页沿用 Hello Agent 的自定义顶栏和左上角抽屉交互，保留标题与紧凑的日期／日周月切换。日时间轴在前，八张摘要卡和昨晚衔接放在其后。历史数据、趋势、宝宝切换、设置、刷新及退出放在菜单内；设置为独立子页面，返回保留浏览日期与视图。昵称保存成功后更新菜单中的宝宝资料。

用户已指定另外五个模块：Agent/MCP 录入、程序内对话、微信小程序认证、Payload CMS 运营、付费会员。内置对话及待补事项后续融合，当前不接入通用祝福会话或 Hello Agent 的领域模型；不建立占位字段或固定录入表单。首期产品限时免费的安排仍以 PRD 为准。

详细产品要求与实施顺序在 [MVP PRD](https://github.com/code-for-people-2026/cfp-mono/issues/391)、[六模块规划](https://github.com/code-for-people-2026/cfp-mono/issues/392) 和 [可视化模块](https://github.com/code-for-people-2026/cfp-mono/issues/394)，运行与迁移边界见 [README](README.md)。

身份模块新增登录恢复、退出、旧凭证绑定、首次创建宝宝与照护邀请码加入；不会把宝宝事实写进聊天文本。撤权/失效清除当前视图，迟到响应不恢复旧上下文。独立身份模式的照片在打开详情时经服务端鉴权读取，微信临时文件随详情/宝宝/身份变化清理。接口与测试方法见 README；可信 Agent、群绑定和运营权限由服务端契约约束，客户端不可声明自己的角色。
